## 개발 모드

코드를 고치거나 기능을 직접 만들 때 쓰는 실행 방식입니다.

| | 로컬 서버 모드 | 개발 모드 |
| --- | --- | --- |
| 실행 방법 | `just serve` | `just dev` |
| 접속 | http://localhost:8000 | http://localhost:5173 |
| 화면을 고치면 | 다시 빌드해야 반영됩니다 | 저장하면 바로 반영됩니다 |
| 백엔드를 고치면 | 껐다 켜야 반영됩니다 | 저장하면 백엔드가 재시작됩니다(돌던 전략도 끊김) |
| 언제 쓰나요 | 프로그램을 이용할 때(장중) | 코드를 고칠 때 |

## 어디를 고치면 되나요

| 하려는 일 | 고칠 곳 |
| --- | --- |
| NH선물 API 호출 코드 추가 | `backend/` 아래 기능별 폴더(예: 인증은 `backend/auth/`). 거래 API 는 `backend/nh_api/client.py` 를 거쳐 부릅니다 |
| 화면에서 부를 주소 추가 | 기능 폴더의 라우트 파일(예: 전략은 `backend/strategy/strategy_routes.py`). `backend/main.py` 가 라우터를 `/api` 아래에 붙입니다 |
| 화면 만들기·고치기 | `frontend/src/screens/`, 공통 골격은 `frontend/src/app/` |
| 설정 항목 추가 | `backend/config.py` 와 `config.example.yaml` |
| 실행 명령 변경 | `justfile` 의 `serve`·`dev` |

## 저장해 둔 응답으로 실행하기

NH선물 서버에 접속할 수 없는 곳에서 화면을 고치고 확인할 때 쓰는 **개발용** 방식입니다. 서버에 묻는 대신 `tests/fixtures/nh/` 에 저장해 둔 응답을 돌려줍니다.

기본값은 실서버이고, 환경 변수를 켤 때만 동작합니다. `just serve`·`just dev` 어느 쪽에도 같은 환경 변수로 켭니다(예: `NH_REPLAY=1 just serve`).

```bat
set NH_REPLAY=1
```

```powershell
$env:NH_REPLAY = "1"
```

`/api/health` 의 `mode` 가 `replay` 이면 저장해 둔 응답으로 답하는 중입니다.

### 이 방식에서 달라지는 것

- **화면에 뜨는 값은 실제 시세나 잔고가 아닙니다.** 접속 토큰과 웹소켓 접속키는 그 자리에서 만들어 낸 값입니다.
- 날짜나 이어받기 키만 다른 요청에는 조회 조건이 같은 기록으로 답합니다. 조회 조건(체결구분 같은 것)이 같은 기록이 없으면 다른 기록 대신 **0건으로** 답합니다. 어느 쪽이든 그 사실을 응답 헤더 `x-nh-replay-match` 에 남깁니다.
- 주문은 저장해 둔 요청과 똑같을 때만 재생됩니다.
- 설정 화면의 인증 정보 저장은 거절됩니다. 사용자 설정 파일을 건드리지 않습니다(모의·실전 전환은 됩니다).
- 종목 마스터를 받으러 나가지 않고 사용자 홈에 받아 둔 파일만 씁니다. 받아 둔 것이 없으면 종목 목록이 비고, 「다시 받기」는 거절됩니다.
- 예수금과 잔고, 주문 내역은 모의 환경의 응답만 저장되어 있습니다. **주문 오류 내역은 저장해 둔 응답이 없어 조회되지 않습니다.**
- 전략 실행·거래 기록·손실 한도·예수금 추이는 `~/NHFutures/state-replay/` 에 따로 쌓여 실서버로 띄운 상태와 섞이지 않습니다(전략 목록만 함께 씁니다).

### 저장해 둔 응답 만들기

저장해 둔 응답은 수집한 기록에서 반입합니다.

```bash
uv run python scripts/import_nh_fixtures.py --source <수집 폴더>
```

실전 환경의 계좌·주문 응답은 금액이 실제 값 그대로여서 **저장소에 올리지 않습니다.** 그 응답까지 두고 쓰려면 `--private-out` 으로 따로 반입합니다. 그 폴더는 `.gitignore` 에 들어 있어 커밋되지 않고, **없어도 프로그램과 테스트는 그대로 동작합니다.**

```bash
uv run python scripts/import_nh_fixtures.py --source <수집 폴더> --private-out tests/fixtures/nh_private
```

**저장소 안의 다른 폴더를 지정하지 마세요.** 반입 자리와 겹치면(같거나 한쪽이 다른 쪽 안이면) 실행이 거부되지만, 저장소 안 아무 곳이나 지정하면 그 금액이 커밋될 수 있습니다.

`NH_REPLAY_PRIVATE_DIR` 로 그 폴더를 다른 자리에서 읽거나(값에 경로), 아예 안 읽게(빈 값) 할 수 있습니다.

## 프로그램이 사용자 폴더에 남기는 것

```
~/NHFutures/
├── config/         설정과 인증 — 밖으로 내보내지 마세요
├── master/         내려받은 종목 마스터
├── state/          화면 상태와 전략 파일
└── state-replay/   저장해 둔 응답으로 띄웠을 때의 상태(개발용)
```

| 파일(`state/`) | 담는 것 |
| --- | --- |
| `ui.json` | 화면 배치·관심종목·차트에 그린 것 |
| `deposit-history.json` | 예수금 추이 |
| `strategies.json` | 전략 목록 |
| `strategy-runs.json` | 실행 |
| `strategy-trades.jsonl` | 거래 기록 |
| `strategy-limits.json` | 손실 한도 |

`state-replay/` 에는 저장해 둔 응답으로 띄웠을 때의 화면 배치(`ui.json`)·실행·기록·한도·예수금 추이가 쌓입니다.

거래 기록 파일은 16MB 가 되면 `strategy-trades.jsonl.old` 로 한 번 교대하고 그 앞 것은 지웁니다. 분석 화면은 두 파일을 함께 읽습니다.

`config` 와 `state` 를 나눈 것은 **「`config` 폴더는 누구에게도 보내지 마세요」가 한 줄로 서게 하기 위해서**입니다. 새어도 곤란할 것 없는 화면 상태는 다른 폴더에 둡니다.

화면 상태 중에서도 **그 컴퓨터, 그 창에서만 뜻이 있는 것은 파일로 옮기지 않고 브라우저에 남습니다.** 밝기, 최근 본 종목, 사이드바 펼침, 종목 화면의 목록 폭과 펼친 무리, 차트와 옵션 화면의 아래 칸 펼침이 그렇습니다. 창 크기에 맞춰 둔 값이 다른 컴퓨터까지 따라오면 오히려 어긋나기 때문입니다.
