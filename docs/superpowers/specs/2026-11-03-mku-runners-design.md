# MKU 해외 자동매매 — ORB(1분봉) · leadlag(실시간) 설계

상태: 구현됨 (2026-11-04, 브랜치 feat/mku-runners)

## 1. 왜

3주차에 팀이 SGX 미니 원달러(MKU) 전략 두 개를 만들었습니다(저장소 `NH-REST-API-Pioneer/pioneer-1st-6team-NFT`, `week03/`).

- **ORB** `week03/strategy_orb.py` + 공용 모듈 `week03/common.py`. 서울·런던·뉴욕 개장 범위 돌파를 1분봉으로 판단합니다.
- **leadlag** `week03/leadlag/ws_trader.py` 의 `Engine`. KRX 달러선물이 짧은 시간에 크게 움직였는데 MKU 가 덜 따라왔으면 MKU 를 따라 들어갑니다. **초 단위 실시간**(웹소켓)으로 판단합니다. 근거 문서는 1분봉으로는 늦다고 결론 냈습니다.

지금 앱(배포 서버 https://nh.silverstn.com)의 파이썬 전략 실행기(`backend/team_pyrun/`)는 국내 미국달러선물 1분봉 전략만 돌립니다. 이 두 전략을 **앱에 올려 해외 모의 계좌로 자동매매**하고, 지금처럼 대시보드에서 보고 결과 zip 을 받게 하려는 것이 이 작업입니다. MKU 해외 모의 지원은 2026-11-03 확인했습니다(현재가·호가·체결 이력 있음).

## 2. 목표 · 하지 않을 것 · 실패로 볼 것

**목표**
1. ORB 파일(`strategy_orb.py`)과 `common.py` 를 「파일 올리기」로 올리면 MKU 1분봉 자동매매가 됩니다. 장 시간은 08:25~20:35 · 20:50~23:50(청산)입니다.
2. leadlag 의 `Engine` 을 떼어 낸 파일 하나를 올리면 KRX 체결 + MKU 호가를 실시간으로 받아 초 단위로 MKU 를 매매합니다.
3. week02 국내 전략은 지금처럼 그대로 돕니다(10/30 리플레이 골든 유지).
4. 「모의 계좌」·「종이」 두 방식, 대시보드, 결과 zip(`journal.jsonl` · `summary.json` · `api_log.jsonl`)은 기존과 같은 모양입니다.
5. Engine 을 떼어 올리는 방법과 새 약속을 작성 규칙 문서와 화면 「작성 규칙」에 텍스트로 적습니다.

**하지 않을 것**
- 두 종목에 짝으로 주문하는 스프레드. leadlag 는 MKU 한 종목만 주문합니다(KRX 는 시세만 봄).
- 자정을 넘기는 실행. 해외 모의계좌가 07:00~24:00 이고 두 전략 모두 날을 넘기지 않습니다. 실행은 하루 단위입니다.
- ORB·leadlag 동시 실행(사용자 결정). 같은 MKU 종목의 「모의 계좌」 실행은 실행기 종류와 상관없이 하나만 받습니다.
- 실전 계좌, 재시작 자동 재개(원칙 3).
- 서머타임 자동 전환. ORB 개장 시각은 전략 Params 가 정합니다.

**실패로 볼 것**
- 응답 없는 주문을 다시 보내 중복 주문이 나가는 것. 기존 1분봉 실행기의 안전장치(결과 모름 표시, 주문 전 잔고 관문, 「확인 필요」)가 실시간 실행기에도 그대로 있어야 합니다.
- 같은 데이터를 넣었는데 week03 백테스트·리플레이와 다른 판단이 나오는 것.
- 기록에 계좌번호·이름·IP·토큰이 남는 것.
- 종이 체결을 모의 계좌 체결처럼 표시·기록하는 것.
- week02 국내 실행이 깨지는 것.

## 4. 해외 MKU 공통 (두 실행기가 같이 씀)

- **API 계층은 팀 코드**(원칙 2). `backend/team_pyrun/api.py` 에 해외 함수를 더합니다. 운영자의 `client().call()` 만 쓰고 `environment="paper"` 고정, 주문은 재시도 없음, 조회만 재시도합니다.
  쓰는 API: `overseas_chart-minute` `overseas_price` `overseas_order` `overseas_order-history` `overseas_open-interest`
  `overseas_deposit` `overseas_product-detail` `overseas_product-expiry`(또는 종목 마스터)
  요청 값·응답 칸은 week03 `nh_client.py`(`ovs_*` 함수)와 운영자 `backend/overseas_futureoption/` 에서 확인합니다.
  저장소 `tests/fixtures/nh/` 에 해외 주문·주문내역·잔고·예수금 기록이 **없으므로** 운영자 코드에서 칸 이름을 확인하고,
  가능하면 모의 서버에서 한 번 받아 기록을 남깁니다(값은 가림).
- **종목.** 「실행 세우기」 종목 검색에서 MKU 월물을 고를 수 있게 합니다. 지금은 미국달러선물만 고를 수 있습니다. 빈칸이면 실행기 종류와 전략에 맞는 기본값을 씁니다: ORB 는 MKU 최근월물, leadlag 는 MKU 최근월물과 KRX 최근월물입니다. 실행이 주문하는 종목은 하나입니다.
- **틱·통화.** MKU 는 틱 0.0001 = US$2.5, 손익·수수료는 USD 입니다. 시작할 때 `overseas_product-detail` 의 틱 단위·틱 가치가 전략 파일의 `TICK` · `TICK_VALUE` 와 다르면 거부합니다(국내와 같은 규칙).
  `summary.json` 과 화면에 통화를 표시합니다.
- **시간표.** 해외 모의계좌는 07:00~24:00 입니다. 실행은 그날 23:55 에 끝냅니다(국내 15:31 자리). 전략이 정한 청산 시각이 먼저 옵니다. 거래소 휴장(20:35~20:50)에는 주문하지 않습니다.
- **주문·체결·잔고.** 기존 `MockAccountBroker` 의 규칙을 해외 API 로 똑같이 적용합니다. 시장가 주문 → 주문내역 체결 확인(0.5초×30) → 결과 모름이면 `blind`·`unresolved` 표시와 주문 전 잔고 관문 → 어긋나면 「확인 필요」입니다.
  해외 체결 상태 코드와 칸 이름은 확인해서 맞춥니다.
- **동시 실행 규칙.** 같은 종목(MKU 월물)의 「모의 계좌」 실행은 1분봉·실시간 실행기를 통틀어 하나만 받습니다. KRX 를 시세로만 보는 leadlag 는 KRX 종목을 막지 않습니다.
- **기록.** 실행 폴더 이름에 시장을 넣지 않아도 됩니다. `run.json` 에 `market`(`domestic`/`overseas`)·`currency`·`kind`(`minute`/`realtime`)를 둡니다.

## 5. ① ORB — 1분봉 실행기 넓히기

**원칙(사용자 결정, 2026-11-03): 판단은 전략 파일이, 주문·안전·기록은 앱이 맡습니다.** 진입뿐 아니라 **청산 판단도 전략 파일이 할 수 있게** 합니다. leadlag `Engine` 과 같은 구조입니다. 앱이 전략마다 손절 규칙을 짐작하지 않습니다.
week02 처럼 청산 판단 함수가 없는 전략은 지금처럼 앱의 공통 청산 규칙(손절·익절·시간·마감)을 씁니다. week02 골든은 그대로 유지됩니다.

- **해외 1분봉.** `overseas_chart-minute` 로 받습니다. 시각은 한국 시간 `exch_tm`·`ref_dt` 입니다(week03 `common.py` 설명과 2026-11-03 모의 조회). 막 끝난 분만 시각순으로 넣는 규칙은 같습니다.
- **전략이 청산을 판단하는 약속** (선택, 있으면 앱의 공통 청산 규칙 대신 씀):
  - 보유 중일 때 앱이 가격이 들어올 때마다 전략의 청산 판단 함수를 부릅니다. 부르는 때는 지금 1분봉 실행기의 `on_price` 자리이고, 가격·그 분 저가·고가·시각·보유 정보(방향·진입가·진입 시각·진입 신호)를 넘깁니다. 전략은 청산 사유(`"손절"`·`"익절"`·`"시간"`·`"마감"` 등) 또는 None 을 돌려줍니다. 함수 이름과 인자 꼴은 빌더가 정해 문서에 적습니다.
  - 앱이 여전히 맡는 것: 그날 실행 끝 시각(해외 23:55, 국내 15:31)의 강제 정리, 중지·오류 정리, 결과 모름·잔고 불일치 「확인 필요」, 주문 재전송 금지. 이 안전 정리는 전략 판단보다 앞섭니다.
  - 기록하는 청산 가격은 지금처럼 주문 체결가(모의 계좌) 또는 종이 체결가입니다. 전략이 손절 가격을 정하면 앱은 그 가격을 「지났는지」 판단을 전략에 맡기고, 체결은 시장가입니다(week02 와 같음).
- **ORB 를 이 약속에 맞추기.** week03 `strategy_orb.py` 의 진입 판정(`SessionBreakout`)과 `backtest.py` 의 청산 규칙(범위 반대편 끝 손절, 진입가 + `target_ticks` 익절, `exit_by`·`hold_min`·23:50 시간 청산)을 담은 앱용 ORB 파일을 만듭니다. 이름은 예를 들어 `strategy_orb_app.py` 이고 `common.py` 와 함께 올립니다. `strategy_orb.py` 의 판정 코드는 고치지 않고 불러 쓰는 것이 좋습니다.
  이 파일은 예제로 `docs/team/examples/` 에 두고, 만드는 법을 작성 규칙 문서에 적습니다.
- **신호 기록·화면.** ORB 신호는 `bar` 대신 `minute`(1분봉) 칸을 가집니다. 기록·화면은 `bar` 가 없으면 `minute` 을 씁니다. `range_high`·`range_low`·`window`·`exit_by`·`target_ticks` 같은 숫자·문자 칸을 기록하고 표에 보여 줍니다. 차트는 `range_high`·`range_low` 를 가격 위 선으로 그립니다.
- **`on_entry` 인자.** 인자를 받으면 진입 신호를 넘깁니다. ORB 의 `on_entry(window)` 는 신호의 `window` 를 받습니다. 인자 이름이 신호 칸 이름과 같으면 그 값을 넘기고, 정확한 규칙은 빌더가 정해 문서에 적습니다. 앱용 ORB 파일이 직접 맞춰도 됩니다.
- **Params 약속 넓히기.** 지금은 `session_start` 등 6칸이 필수입니다. ORB `Params` 에는 `hold_min`·`flatten_at` 만 있습니다.
  없는 칸은 시장 시간표에서 채웁니다: 해외는 장 시작 08:25, 진입 끝 = 청산 시각, 청산 = `flatten_at` 또는 23:50. week02 국내 전략은 지금 칸을 그대로 씁니다.
- **휴장 구간.** 20:35~20:50 에는 진입·청산 주문을 내지 않습니다. 전략이 이 사이에 청산을 말하면 20:50 첫 가격 때 주문합니다.
- **장중 시작·같은 날 재시작(제 판단).** 시작 전 준비 봉에서 이미 진입 신호가 났던 개장(window)은 「이미 진입함」으로 봅니다(백테스트라면 그때 들어갔을 것이므로). 같은 날 앞선 실행의 `trade` 기록에 남은 window 도 이어받아 `on_entry(window)` 로 되살립니다. 개장마다 한 번 규칙이 실행을 다시 세워도 지켜집니다. 이를 위해 `trade` 줄에 진입 신호의 `window` 를 남깁니다.
- **골든.** week03 `results/data/bars_1m_MKUX26.csv` 와 week03 `backtest.py`(ORB) 결과(`results/backtest_orb/`)를 기준으로 삼습니다. 같은 1분봉 리플레이가 같은 거래를 내야 합니다. 체결 기준가·슬리피지·수수료는 백테스트 설정에 맞춰 비교합니다. 맞지 않으면 차이를 진단해 보고합니다. 내려받은 코드는 실행하지 않습니다.

## 6. ② leadlag — 실시간 실행기

### 6-1. 실행기
- 앱 실시간 허브(`backend/realtime/`)의 연결(재접속·pingpong·구독 한도 관리)을 씁니다. 구독은 KRX 종목 체결(`KA`), MKU 호가(`FB`), MKU 체결(`FA`, 기록용)입니다.
  **허브가 화면용으로 100ms씩 묶기 전의 원문 메시지를 받은 순서 그대로 받습니다**(제 판단). leadlag 는 1초 안의 선후로 판단하므로, 묶음(호가는 마지막 것만, 체결·호가 순서 사라짐)으로는 ws_trader 와 같은 판단을 보장할 수 없습니다.
  이를 위해 허브의 묶기 앞(`hub.py` `_on_data` 자리)에 서버 내부 구독자를 끼우는 `# 팀:` 갈고리를 둡니다. 구독 등록은 운영자 `RunPump` 처럼 실행 id 이름의 허브 클라이언트로 `declare` 합니다(묶음은 받되 버림).
- 허브는 asyncio 에서 돕니다. 실행이 그 큐를 빨리 비우는 방식은 빌더가 정합니다. 큐가 차면 오래된 것부터 버리므로 판단이 늦으면 안 됩니다.
  주문·체결 확인처럼 막히는 일은 별도 스레드나 `to_thread` 로 돌려 큐 비우기를 막지 않게 합니다.
- **Engine 에 넣는 것** (ws_trader `Trader.on_dom` / `on_ovs` / `timer` 와 같게):
  - KRX 체결: `tick_div=="1"`·체결수량>0 만 → `on_krx(price, monotonic, exch_tm[:6])`
  - MKU 호가: 1단 매수·매도 → `on_quote(bid, ask, monotonic, ko_exec_tm[:6])`
  - 1초마다 `on_timer(monotonic, 지금 HHMMSS)`
  - 시각 기준은 ws_trader 처럼 받은 순간의 단조 시계입니다.
- **Engine 이 돌려준 행동 실행.** `{"act":"enter"|"exit","side":±1,"ref":…}` →
  - 「모의 계좌」: MKU 시장가 1계약. 공통 4절의 해외 주문 안전장치를 그대로 씁니다. 체결가로 `filled_entry`/`filled_exit` 를 부릅니다.
    체결을 확인 못 하면 ws_trader 처럼 호가로 기록하고 끝내지 **않습니다**. 1분봉 실행기 규칙대로 결과 모름 → 잔고 관문 → 「확인 필요」 로 갑니다.
  - 「종이」: 반대 호가(`ref`)로 체결한 것으로 기록합니다(ws_trader 종이 방식).
- **청산 판단은 Engine 이 합니다**(익절·손절·보유 시간·15:40). 실행기는 실행 끝(중지·장 끝·오류) 때 보유가 남아 있으면 스스로 청산 주문을 내고 `filled_exit(…, "실행 종료 정리")` 를 부릅니다.
- **시작 검사.** MKU 잔고가 남아 있으면 거부합니다(ws_trader 와 같음). 모의 환경이 아니면 「모의 계좌」 방식을 거부합니다. 같은 MKU 「모의 계좌」 실행이 있으면 거부합니다.
- **끝.** 전략 Params 의 `flatten_at` 이후 + 여유(ws_trader `--until` 15:45 와 같음) 또는 중지·오류입니다. 남은 보유를 정리하고 요약을 씁니다.
- **기록.** 기존 `journal.jsonl` 꼴(`event` `signal` `order` `fill` `trade`)을 씁니다. `signal` 은 진입·청산 신호 때만 남기고 `dk`·`rho`·`spread`·`expected`·`followed` 를 담습니다. `trade` 에 ws_trader 와 같은 `gross_ticks`·`net_ticks`·`net_usd`·`held_s` 를 둡니다.
  받은 메시지 원문(`raw.jsonl`)은 남기지 않습니다(용량). 대신 1분마다 KRX 가격·MKU 중간값·호가 차이를 한 줄 `minute` 으로 남겨 차트와 사후 분석에 씁니다. `api_log.jsonl` 은 주문·조회만입니다.
- **골든.** leadlag 저장소 `results/live/<날짜>/raw.jsonl.gz` 녹화를 같은 순서로 Engine 에 넣는 리플레이가 ws_trader `replay_live.py` 결과와 같은 신호를 내야 합니다. 녹화가 없거나 너무 크면 손으로 만든 메시지 순서로 시험합니다.

### 6-2. 실시간 전략 파일 약속 (Engine 떼어 올리기)
- 파일 하나에 `LiveParams`(dataclass)와 판단 클래스(`Engine`)를 둡니다. 판단 클래스는 `on_krx` · `on_quote` · `on_timer` · `filled_entry` · `filled_exit` 를 가지고, 시세 메서드는 행동 dict 또는 None 을 돌려줍니다.
  `pending` · `pos` · `stops` 속성은 화면 표시에 씁니다(있으면).
- 실행기 종류는 이 약속으로 알아봅니다: `on_minute` 이 있으면 1분봉, `on_krx`/`on_quote` 가 있으면 실시간입니다. 둘 다 있으면 오류입니다.
- 떼는 법(문서에 그대로 적을 것): `ws_trader.py` 에서 `TICK`·`TICK_USD`·`FEE_TICKS` 상수, `LiveParams`, `Engine` 만 남기고 `Recorder`·`Trader`·`main`·`websockets`·`nh_client`·`fee_test`·`ws_probe` import 를 지웁니다. 이름은 예를 들어 `strategy_leadlag.py` 로 합니다.
  표준 라이브러리 외 import 가 없으면 됩니다. 실제 떼어 낸 예제 파일을 저장소 `docs/team/examples/strategy_leadlag.py` 에 둡니다.
- 실행 세우기 폼은 실시간 전략을 고르면 KRX 종목(신호용)과 MKU 종목(주문용) 두 칸을 보여 줍니다(검색해서 고르기, 빈칸 = 최근월물).

### 6-3. 화면
- 실행 목록·머리줄·상태 막대·아래 표 탭은 기존 그대로입니다. 배지에 「실시간」을 더합니다.
- 상태 막대: 보유(방향·진입가·보유 초) · 지금 KRX 가격 · MKU 매수/매도 호가 · 최근 `dk`/`rho`(마지막 판단) · 오늘 손절/한도 · 오늘 손익(USD).
