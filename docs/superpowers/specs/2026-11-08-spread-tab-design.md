# 스프레드 탭 — 실행기 올리기 + 앱 창구(`ctx`) 설계

- 상태: 구현됨 (2026-11-09) — 구현·작성 규칙은 `docs/team/spread-runner-convention.md` 가 기준 (초안 2판: 빌더 확인 질문 두 개에 사용자 답 반영) · 브랜치 `feat/spread-tab`
- 관련: 파이썬 전략 탭(`backend/team_pyrun/`, `docs/team/strategy-file-convention.md`) — **그대로 둔다**

## 1. 왜

4주차 과제는 복수상품·스프레드다. 전략은 아직 없고(롤링 β 방식 예정) 종목도 정해지지 않았다 — 국내 미국달러선물 × SGX MKU일 수도,
해외 계좌의 **난방유(HO) × 가솔린(RB)** 일 수도, 월물 간 스프레드일 수도 있다. 팀은 **전략이나 종목이 바뀔 때마다 앱을 고치지 않고**
자기가 짠 실행기 파일을 올려 모의계좌에서 돌리고, 앱에서는 기록과 대시보드를 보고 싶다.

그래서 흔한 자동매매 플랫폼(QuantConnect LEAN·Backtrader·MetaTrader)의 방식을 따른다: **팀 코드가 매매 흐름 전체를 짜고,
주문·시세·잔고는 앱이 주는 창구(`ctx`)로만 쓴다.** 앱은 증권사 접속·주문 안전·기록·화면을 맡는다.

확인된 사실 (2026-11-08):
- 서버 앱(해외 모의)에서 `HOZ26`·`RBZ26` 현재가·호가가 나오고 주문 화면에서 주문할 수 있는 상품이다(사용자 확인).
- 종목 마스터 `cme_fut.mst` 에 HO·RB 줄이 있고 거래소 `FCME`, 틱 0.0001, 틱 가치 US$4.2, 최근월물 표시가 들어 있다.
- 해외 주문(`api.ovs_market_order`)은 종목 코드만 받고 수량을 받는다. 시세·차트 조회는 거래소 코드(`exch_cd`)가 필요하다 — 마스터에서 읽는다.
- 국내 품목 세부정보(`api.product_detail`)에 품목별 틱·틱 가치가 있다. 국내 주문(`api.market_order`)도 수량을 받는다.
- 종목 하나의 지금 세션(열림·쉼)을 판정하는 운영자 코드가 있다(`backend/sessions/judge.py` `judge_domestic`·`judge_overseas`, 시간표 `sessions/service.py`).

## 2. 목표

1. 「전략주문」 메뉴에 **「스프레드」 탭**을 「파이썬 전략」 옆에 새로 둔다.
2. 팀이 **실행기 파일**(`run(ctx)`)과 그것이 import 하는 옆 파일들을 올리고, 모의 계좌 또는 종이로 실행을 세운다.
3. 다리(종목)는 **국내·해외 어떤 선물이든** — 종목 정보(최근월물·틱·틱 가치·통화·거래소·시장)는 마스터에서 찾는다.
4. 실행은 **「중지」를 누를 때까지 날을 넘겨 계속** 돈다. 다리의 장이 쉬면 기다리고, 다시 열리면 이어서. 보유는 날을 넘겨 들고 갈 수 있다.
5. 어떤 실행기든 **앱의 주문 안전 규칙**(9장)이 똑같이 걸린다.
6. 화면에서 다리별 보유·체결·통화별 손익, 실행기가 남긴 값(`ctx.log`)의 차트, 사건 기록, API 기록을 본다.
7. 서버 없이 받아 둔 1분봉으로 같은 실행기를 돌려 보는 **재생**이 된다.

## 3. 하지 않는 것

- 초 단위 실시간 구독(체결·호가 스트림)을 `ctx` 로 주기 — v1 은 1분봉 + 그때그때 현재가·호가 조회. 나중에 붙일 자리만 남긴다(`ctx` 이름을 막지 않음).
- 지정가·스탑·거래소 스프레드 주문·옵션. 시장가만.
- 실전 서버. 모든 주문은 모의(`paper`) 서버로만(파이썬 전략 탭과 같다).
- **서버 재시작 뒤 자동 재개.** 사용자 결정(5장): 끝내고 사람이 확인한다. 남은 보유는 사람이 「이어받기」로 새 실행에 넘긴다(8장) — 앱이 저절로 넘기지 않는다.
- 실행기가 자기 NH 클라이언트로 주문하기. 주문·시세·잔고는 `ctx` 로만 — 그 밖의 길은 막지 못하므로(샌드박스가 아님) 약속과 문서로 지킨다.
- 파이썬 전략 탭의 동작 변경. 공용 코드를 손볼 때도 그 탭의 시험은 그대로 통과해야 한다.
- 매일 자동 시작. 실행이 날을 넘겨 계속 살아 있으므로 필요 없다.
- 통화 환산(원↔달러) 합계. 손익은 통화별로 따로 보인다.

## 4. 이러면 실패 (안티골)

- 결과를 모르는 주문 뒤에 그 실행에서 주문이 또 나간다.
- 앱이 모르는 보유(손으로 산 것, 다른 실행의 것)를 실행이 정리하거나 조정한다.
- 실행기 파일 하나의 오류·무한 대기가 다른 실행이나 앱 전체를 멈춘다.
- 팀이 전략이나 종목을 바꿀 때 앱 코드를 고쳐야 한다.
- 계좌번호·토큰·키가 기록·결과 묶음에 남는다.
- 장이 쉬는 동안 주문이 나간다.

## 5. 사용자가 정한 것

- 방식: **실행기 올리기 + 앱 창구(`ctx`)** (플랫폼 방식). 목표 보유 도우미(`ctx.target`)도 함께 준다.
- 화면: 기존 「파이썬 전략」 탭은 그대로, 옆에 **「스프레드」 탭**.
- 수명: 실행은 「중지」까지 날을 넘겨 계속. 장이 쉬면 기다렸다가 다음 개장에 이어서 매매.
- 서버 재시작(배포·재부팅·프로세스 종료) 때: **실행을 끝내고 잔고만 확인** — 보유가 남았거나 잔고를 못 읽으면 「재시작 · 확인 필요」. 이어 돌리지 않는다.
- **앱을 끌 때(배포 등) 보유는 정리하지 않는다.** 남은 보유는 **사람이 확인하고 「이어받기」** 로 새 실행에 넘긴다(8장). 「확인 필요」로 멈춘 실행의 보유도 같다.
- **「중지」·오류 뒤 정리는 짝을 유지했다가 함께**: 모든 다리의 장이 열려 있을 때 한꺼번에 시장가로 정리한다. 한 다리라도 장이 쉬면 짝을 그대로 들고 「정리 대기」로 기다린다(한 다리만 헤지 없이 남기지 않게).
- 종목: 국내·해외 아무 선물(예: HO × RB). 모의 서버에서 HO·RB 시세·주문이 되는 것을 확인함.
- 데이터: 1분봉 + 현재가·호가 조회(초 단위는 나중) — 사용자가 따로 답하지 않아 제 결정으로 두고 이 문서에서 확인받는다(15장).

## 6. 실행기 파일 약속

- **올리는 곳**: 스프레드 전용 폴더 `~/NHFutures/spreads/`(파이썬 전략 폴더와 섞지 않음). 올리기 규칙(이름·크기·UTF-8·덮어쓰기 묻기)은 파이썬 전략 탭과 같다.
- **실행기 파일** = 모듈에 다음이 있는 `.py`:
  - `LEGS` — 다리 이름 → 종목. 값은 품목 뿌리(`"HO"`, `"RB"`, `"A75"`, `"MKU"`) 또는 정확한 종목 코드(`"HOZ26"`). 뿌리면 앱이 마스터에서 **최근월물**을 고른다.
    앱은 실행을 세우기 전에 `LEGS` 를 읽어 시작 화면에 다리와 고른 월물을 보여 주고, 시작 잔고를 확인한다.
  - `run(ctx)` — 실행 하나에 한 번 불린다. 돌려주면(return) 실행이 끝난다.
  - 있으면 쓰는 것: `TITLE`·`NAME`(파이썬 전략 탭과 같은 규칙), `MAX_QTY`(다리별 최대 보유 기본값, 시작 화면에서 바꿀 수 있음).
- **옆 파일**: 실행기가 맨 위에서 import 하는 같은 폴더의 `.py`(전략 파일 등). 파이썬 전략 탭과 같은 불러오기 규칙(맨 위 import, 불러오는 동안만 경로에 있음).
- 실행기 파일이 앱에 없는 모듈(예: 자기 `nh_client`)을 import 하면 불러오기 오류다 — 주문은 `ctx` 로만 한다. (파이썬 전략 탭의 「판단 부분만 골라 쓰기」는 여기엔 쓰지 않는다: 실행기 자체가 매매 흐름이므로.)
- 목록에는 파일마다 `LEGS`·`TITLE`·오류를 보인다(파이썬 전략 탭 카드와 같은 꼴).

## 7. 앱 창구 `ctx`

실행기는 아래만으로 시세를 보고 주문한다. 이름은 바꿔도 되지만(빌더 몫) 이 의미는 지킨다. 모든 시각은 한국시간.

| 이름 | 뜻 |
|---|---|
| `ctx.leg(name)` | `LEGS` 의 다리. 칸: `name` `sym` `product`(뿌리) `market`(`domestic`/`overseas`) `exchange` `currency` `tick` `tick_value` `point_value`(= tick_value / tick) `expiry`(만기일) |
| `ctx.bars(legs, count)` | 과거 1분봉, 다리끼리 **같은 시각으로 맞춘** 줄들(오래된 것부터). 한 다리에 거래가 없던 분은 직전 종가로 채우고 그 칸에 채웠다는 표시 |
| `ctx.next_minute(legs)` | 다음 1분이 끝날 때까지 기다렸다가 그 분의 맞춘 줄을 돌려준다. 다리 중 하나라도 장이 쉬면 열릴 때까지 기다린다(상태 「장 쉼」). 중지·끝이면 `None` |
| `ctx.quote(leg)` | 지금 현재가·매수/매도 1호가(조회 한 번) |
| `ctx.position(leg)` | 이 실행이 아는 보유(계약, 매수 +). 앱이 계좌 잔고와 대조해 둔 값. 이어받은 실행은 시작부터 이어받은 보유 |
| `ctx.inherited` | 이어받은 실행이면 `{"from": 앞선 실행 id, "ended_reason": 끝 까닭, "legs": {다리: {"qty", "avg_price"}}}`(평균가 모르면 `None`), 아니면 `None`. 실행기는 이것으로 자기 상태(롤링 β 창, 진입 기준 등)를 되살린다 — 되살리기는 실행기 몫 |
| `ctx.order(leg, qty)` | 시장가 주문 하나(`qty` 부호 = 방향). 체결 결과(수량·평균 체결가)를 돌려준다. 결과를 아는 실패(거부·장 닫힘·한도 초과)는 예외 `OrderRejected` |
| `ctx.target({leg: qty, ...})` | 목표 보유로 맞추기 — 다리마다 차이만큼 적힌 순서대로 `order`. 한쪽 다리만 체결되면 아래 규칙 |
| `ctx.log(name, value, **fields)` | 대시보드 차트·사건 기록에 남길 값(예: `ctx.log("z", 2.3, beta=0.82)`) |
| `ctx.running()` | 「중지」 요청이나 멈춤이 없으면 True |
| `ctx.now()` · `ctx.sleep(s)` | 지금 시각 · 기다리기(중지면 바로 깸). 재생에서는 재생 시계 |
| `ctx.market_open(leg)` | 그 다리의 장이 지금 열렸는가 |
| `ctx.roll(name)` | 그 다리를 다음 월물로 바꾼다. **그 다리 보유가 0일 때만** — 보유가 있으면 `OrderRejected`. 만기 관리는 실행기 몫 |

**`ctx.target` 의 한쪽 다리 규칙** (제 결정, 15장):
- 뒤 다리 주문이 **거부**(결과를 앎)되면, 같은 `target` 에서 이미 체결된 다리를 **시장가로 한 번 되돌린다**(짝이 반쪽으로 남지 않게). 되돌리기도 거부되면 멈춤(「확인 필요」).
- 어느 다리든 **결과를 모르면** 더 주문하지 않고 멈춤(9장).
- `ctx.order` 로 직접 주문할 때의 짝 맞추기는 실행기 몫이다.

예외: 멈춘 실행에서 `ctx.order`·`ctx.target` 은 예외 `Halted` 를 올린다(주문 안 남).

## 8. 실행 수명

- 실행 하나 = 실행기 파일 하나 × 「중지」까지. 상태: `준비` → `진행 중` / `장 쉼` → (`확인 필요`) → `끝` / `오류`.
- **시작**(실행 세우기): 파일·방식(종이 / 모의 계좌)·다리별 월물(기본 최근월물, 바꿀 수 있음)·다리별 최대 보유·분당 주문 상한을 정한다.
  모의 계좌는 확인 화면을 한 번 지난다. 시작할 때 다리 종목의 **계좌 잔고가 모두 0** 이어야 한다(아니면 거부) — 아래 「이어받기」만 예외.
- **이어받기**(사용자 결정, 사람이 하는 재개): 끝난 모의 계좌 실행의 다리 종목에 보유가 남아 있으면, 그 실행에서 「이어받기」로 새 실행을 세울 수 있다.
  - 같은 실행기 파일·같은 다리 종목·모의 계좌일 때만. 확인 화면에 **계좌의 지금 잔고**(다리별 수량·평균가), 앞선 실행의 끝 까닭,
    앞선 실행이 「확인 필요」였으면 그 까닭(결과 모름 주문 등)과 「주문내역을 먼저 확인하세요」 경고를 보인다. 사람이 확인해야 시작된다.
  - 새 실행은 **확인 순간 다시 읽은 계좌 잔고**를 시작 보유로 삼는다(화면에 보인 값과 다르면 시작하지 않고 다시 확인하게). 평균가는 계좌 잔고의 평균가, 없으면 앞선 실행 기록.
  - 이어받을 수 있는 앞선 실행은 하나 — 이어받으면 그 실행은 「넘겨줌(→ 새 실행 id)」으로 표시되어 다시 이어받을 수 없다.
  - 결과 모름 주문이 있었던 실행이라도 사람이 주문내역·잔고를 확인했다면 이어받을 수 있다(그 판단을 사람이 한다). 앱은 그 주문을 다시 내지 않는다.
  - 손익은 새 실행 안에서 이어받은 평균가 기준으로 센다. 앞선 실행과의 연결(id)은 양쪽 기록에 남긴다.
- 실행기 `run(ctx)` 는 실행마다 **별도 스레드**에서 돈다. 실행기가 돌려주면 「끝」, 예외면 「오류」.
- **「중지」**: `ctx.running()` 이 False 가 되고 `next_minute`·`sleep` 이 깬다. 실행기가 정해진 시간(예: 30초) 안에 돌려주지 않아도
  앱은 그때부터 `ctx` 주문을 받지 않는다. 그 뒤 **남은 보유를 앱이 정리**한다(모의 계좌, 멈춤이 아니면):
  모든 다리의 장이 열려 있으면 바로 다리마다 시장가로, 한 다리라도 쉬면 짝을 그대로 들고 **「정리 대기」** 로 기다렸다가 모두 열리면 한꺼번에(사용자 결정).
  정리 중 한 다리가 거부되면 열린 다리는 마저 정리하고 10초 뒤 같은 다리를 다시(파이썬 전략 탭처럼 3번까지, 그 뒤 멈춤), 결과를 모르면 멈춤.
  「정리 대기」 중에 앱을 끄면 정리하지 않고 끝난다(다시 켤 때 「재시작 · 확인 필요」 → 이어받기 또는 손 정리).
- **오류**(실행기 예외): 「중지」와 같이 정리한다(파이썬 전략 탭과 같은 규칙).
- **앱을 끌 때**: 새 실행을 막고, 도는 실행에 중지를 알린다. **보유는 정리하지 않는다**(사용자 결정 — 날을 넘겨 드는 전략이 배포 때마다 청산되지 않게).
  실행은 끝나고, 다시 켤 때 잔고를 확인해 보유가 있으면 「재시작 · 확인 필요」 — 사람이 「이어받기」로 다시 세운다.
- **앱을 켤 때**: 끝나지 않은 실행 폴더를 잔고 확인만 하고 닫는다(주문 없음) — 파이썬 전략 탭 `recover` 와 같다.
- 실행 폴더: `~/NHFutures/state/spreads/<시작일>_<NAME>_<orders|paper>[_n]/` — `run.json` `journal.jsonl` `api_log.jsonl` `summary.json`.
  요약은 **날마다**(거래일 기준) 와 **실행 전체** 를 함께. 손익·수수료는 통화별.

## 9. 앱 안전 규칙 (모든 실행기)

- 모든 NH 호출은 앱 클라이언트(`runtime.client().call`)로, 모의(`paper`) 환경에서만. 주문은 재시도하지 않는다.
- 주문 결과를 모르면(응답 없음·번호 없음·확인 시간 안에 체결 확인 안 됨) **그 실행은 멈춤(「확인 필요」)** — 더 주문하지 않고, 중지·끝에도 정리하지 않는다.
  파이썬 전략 탭 `broker.py` 의 규칙(주문 전 잔고 관문, `blind`·`unresolved` 표지)을 수량·종목이 일반화된 꼴로 쓴다.
- 한도: 다리별 **최대 보유**(절댓값, 시작 화면, 기본 `MAX_QTY` 또는 5) · **분당 주문 수**(기본 10). 넘는 주문은 `OrderRejected`.
- 장이 쉬는 다리로의 주문은 내지 않고 `OrderRejected`(줄 세워 두지 않음).
- 보유 중엔 주기적으로(예: 30초) 다리마다 계좌 잔고와 대조. 다르면 멈춤.
- **같은 종목에 모의 계좌 실행은 하나** — 스프레드 탭과 파이썬 전략 탭을 통틀어(한 종목을 두 실행이 주문하지 않게).
- 기록은 쓰는 순간 계좌·키·토큰을 지운다(파이썬 전략 탭 `journal.scrub`, 해외 값 가리기 `mask_unlisted` 그대로).

## 10. 종목·시장 정보

- 마스터(`backend/master/`)에서 다리를 찾는다: 국내 선물 파일과 해외 선물 파일들(`cme_fut` `etc_fut` `lme_fut` 등). 뿌리 → 최근월물은 마스터의 최근월물 표시.
- 틱·틱 가치: 마스터 값을, 시작할 때 품목 세부정보(국내 `product_detail`, 해외 `ovs_product_detail` — 해외는 품목 그룹이 여럿일 수 있음)와 맞춰 본다. 다르면 시작 거부.
- 장 열림·쉼: 운영자 `sessions`(시간표 + `judge_domestic`/`judge_overseas`). 시간표를 모르면(`unknown`) 그 다리는 「장 쉼」으로 보고 주문하지 않는다.
- 시세·차트·주문·잔고는 시장별(국내/해외) 팀 API 함수를 쓴다. 해외 시세·차트의 거래소 코드는 마스터에서.

## 11. 화면 — 「스프레드」 탭

파이썬 전략 탭의 자리·클래스를 그대로 따른다.
- 왼쪽: ① 실행기 파일 카드(올리기·지우기·폴더 다시 읽기·「작성 규칙」) ② 실행 목록(상태·방식·다리·누적 손익).
- 오른쪽: 머리줄(제목·상태·「중지」) · 상태 막대(다리별 종목·보유·현재가, 통화별 오늘/누적 손익, 멈춤 까닭) ·
  차트(다리별 가격 + `ctx.log` 값 중 고른 것) · 아래 표(체결 · 사건 기록 · API 기록) · 날짜별 요약.
- 「실행 세우기」 폼: 파일, 방식, 다리별 월물(종목 고르기), 다리별 최대 보유, 분당 주문 상한. 모의 계좌는 확인 얼굴.
- 끝난 실행에 보유가 남아 있으면 그 실행 화면에 **「이어받기」** 단추(8장) — 확인 얼굴에 지금 잔고·앞선 끝 까닭·경고.
- 「정리 대기」 상태는 머리줄에 어느 다리의 장을 기다리는지와 함께 보인다.
- 결과 내려받기(zip): 파이썬 전략 탭과 같은 파일들.

## 12. 재생

`uv run python -m backend.team_spread.replay <실행기.py> <다리이름>=<1분봉.csv> ...` — 같은 실행기를 서버 없이 돌린다.
`ctx` 를 csv 로 채운 것: 시계는 봉 시각, 체결은 종이(다음 봉 시가 ± 슬리피지 1틱, 수수료는 시장별 종이 값), 장 쉼은 봉이 없는 구간.
결과는 실행 폴더와 같은 꼴(`state/spreads/…_replay`). csv 칸은 파이썬 전략 재생과 같은 차트 칸.

## 13. 코드 자리

- 백엔드 `backend/team_spread/`(팀 코드, 운영자 폴더와 섞지 않음), 라우트 `/api/team/spread/...`(`backend/main.py` 에 연결, 시작·종료 훅 포함).
- 파이썬 전략 탭의 부품(올리기 규칙, 불러오기 격리, `broker` 의 주문 안전, `apilog`, `journal`, `markets` 어댑터)을 **고쳐 쓰거나 일반화해 공유**한다 —
  일반화할 때 파이썬 전략 탭 시험 3800여 개는 그대로 통과해야 한다.
- 화면 `frontend/src/screens/team/spread/`, 데이터 `frontend/src/data/spread.ts`, 메뉴 「전략주문 › 스프레드」.
- 문서 `docs/team/spread-runner-convention.md`(화면 「작성 규칙」 과 같은 글) + 예제 실행기 `docs/team/examples/spread_rolling_beta.py`
  (간단한 롤링 β, 모양을 보이려는 것 — 수익 전략 아님, 재생 시험이 돌림). AI 용 프롬프트(`strategy-file-prompt.md`)에 스프레드 실행기 절을 더한다.

## 14. 빌더에게 맡기는 것

- `ctx` 함수의 정확한 이름·꼴(7장의 의미만 지키면 됨), 봉 맞추기의 세부(어느 다리도 거래 없던 분 처리).
- 과거 1분봉을 몇 개까지 줄 수 있는지(차트 API 한도·쪽 넘기기)와 그 한도를 넘는 `count` 의 처리.
- 해외 품목 세부정보의 품목 그룹을 어떻게 찾을지, 다리별 수수료를 어디서 읽을지.
- 「중지」 뒤 실행기를 기다리는 시간, 잔고 대조 주기, 대시보드 차트 꾸밈.
- 파이썬 전략 탭 코드에서 무엇을 공유 모듈로 꺼낼지.

## 15. 제가 정한 것 (검토해 주세요)

1. **데이터는 1분봉 + 현재가·호가 조회**까지. 초 단위 구독은 나중.
2. **`ctx.target` 의 한쪽 다리 규칙**: 거부면 체결된 다리를 한 번 되돌림, 결과 모름이면 멈춤.
3. (사용자가 정함 — 5장으로 옮김: 끌 때 정리 안 함 + 사람이 이어받기, 중지 정리는 짝을 유지했다가 함께)
4. 실행기는 **`LEGS` 상수**를 꼭 가진다(시작 화면·시작 잔고 확인을 실행 전에 하려고).
5. 다리별 최대 보유 기본 **5계약**(`MAX_QTY` 가 있으면 그 값; 시작 화면에서 다리마다 따로 바꿈 — 다리 이름 → 수의 dict), 분당 주문 **10건**.
6. 스프레드 전용 폴더 `~/NHFutures/spreads/` (파이썬 전략과 섞지 않음).
7. 월물 넘기기는 **실행기 몫**(`ctx.roll`, 그 다리 보유가 0일 때만).
8. 통화 환산 없이 **통화별 손익**. 날(거래일) 경계는 한국시간 **07:00**. 체결가를 읽지 못한 체결(`Fill.price_known` False — 기준가 사용)이 든 손익은 「추정」으로 표시.
9. 재생(csv)을 v1 에 넣는다.
10. 이어받기는 **같은 실행기 파일·같은 다리 종목**일 때만, 앞선 실행 하나를 한 번만. 시작 보유는 확인 순간의 계좌 잔고.
11. 중지 정리 중 거부된 다리는 10초 뒤 3번까지 다시(파이썬 전략 탭과 같음), 그 뒤 멈춤.
12. (구현에서 정함) 국내 다리는 v1 에서 **주간 장만** 다룬다(야간은 쉼). 중지 뒤 주문은 `Halted` 가 아니라 `OrderRejected("중지됨")`. `ctx.roll` 뒤의 옛 다리 객체는 낡은 것이라 거부.

## 16. 첫 모의 장중에 확인할 것

- 해외 CME 상품(HO·RB)의 주문 상태 코드·잔고 칸 이름(MKU 와 같은 해외 응답인지) — 파이썬 전략 탭 12장과 같은 순서: 종이 → 모의 계좌 첫 체결 → `api_log` 확인.
- CME 에너지의 장 쉼 시간이 시간표 판정과 맞는지.
- 2계약 이상 주문의 체결 확인(부분 체결 표시)이 1계약과 같은지.
