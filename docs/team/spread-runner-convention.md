# 스프레드 실행기 작성 규칙

「전략주문 › 스프레드」에 올리는 `.py` 파일 하나(실행기)를 어떻게 쓰는지 적은 문서입니다.
파이썬 전략 탭과 달리 **실행기가 매매 흐름 전체를 직접 씁니다** — 두 종목 이상을 보고 `ctx.target` 으로 짝 주문을 냅니다.
앱은 시세 공급·주문 안전장치·잔고 대조·정리·기록을 맡습니다. 예제는 `docs/team/examples/spread_rolling_beta.py`(모양을 보이려는 예제, 수익 전략 아님).
AI 에게 쓰게 할 때는 `strategy-file-prompt.md` 의 「스프레드 실행기」 절을 붙여 넣으세요.

## 1. 파일의 약속

올리는 곳은 `~/NHFutures/spreads/` 입니다(파이썬 전략 폴더와 섞이지 않음). 파일 이름 규칙·크기·덮어쓰기 묻기는 파이썬 전략 탭과 같습니다.

| 이름 | 필수 | 뜻 |
|---|---|---|
| `LEGS` | 예 | `{"ho": "HO", "rb": "RB"}` — 다리 이름 → 종목. 이름은 영문·숫자·`_`. 값은 품목 뿌리(앱이 마스터에서 최근월물을 고름) 또는 정확한 종목 코드. 공백·`/` 금지, 비면 안 됨 |
| `run(ctx)` | 예 | 인자 **하나**(`ctx`)만 받는 함수. 실행마다 별도 스레드에서 한 번 불림 |
| `TITLE` | 아니오 | 화면 제목. 없으면 모듈 문서 첫 줄, 그것도 없으면 `NAME` |
| `NAME` | 아니오 | 영문·숫자·`_`·`-`. 없으면 파일 이름. 기록 폴더 이름에 쓰임 |
| `MAX_QTY` | 아니오 | 다리별 최대 보유의 기본값(양의 정수). 시작 화면에서 다리마다 바꿈 |

- `LEGS` 와 `run` 이 모두 없는 `.py` 는 실행기가 아니라 **옆 모듈**로 셉니다. 옆 모듈 import 는 **파일 맨 위에서**만 하세요.
- 앱에 없는 모듈(`requests`·자기 NH 클라이언트 등)을 import 하면 불러오기 오류입니다. 주문은 `ctx` 로만 합니다.
- 같은 파일을 고쳐도 돌던 실행은 처음 것 그대로입니다.

## 2. `ctx` — 시세와 주문의 유일한 창구

| 이름 | 뜻 |
|---|---|
| `ctx.leg(name)` | `LEGS` 의 다리 객체(`name` `sym` `product` `market` `exchange` `currency` `tick` `tick_value` …) |
| `ctx.bars(legs, count)` | 과거 1분봉, 다리끼리 같은 시각으로 맞춘 줄(오래된 것부터). 거래가 없던 다리의 분은 직전 종가로 채우고 `filled=True` |
| `ctx.next_minute(legs)` | 다음 1분이 끝날 때까지 기다렸다가 맞춘 줄 `Minute` 를 돌려줌(`m.date` `m.time` `m.legs[이름].open/high/low/close/volume/filled`). 다리 하나라도 장이 쉬면 열릴 때까지 기다림(상태 「장 쉼」). 중지면 `None` |
| `ctx.quote(leg)` | 지금 현재가·매수/매도 1호가 |
| `ctx.position(leg)` | 이 실행이 아는 보유(계약, 매수 +) |
| `ctx.inherited` | 이어받은 실행이면 아래 모양의 dict, 아니면 `None`(3장) |
| `ctx.order(leg, qty)` | 시장가 주문 하나. `qty` 는 **정수(`int`)** — 부호 = 방향(매수 +). 0 이면 아무것도 안 하고 `None`. `Fill` 을 돌려줌 |
| `ctx.target({leg: qty, …})` | 목표 보유(**정수**)로 맞춤 — 다리마다 (목표 − 지금 보유)만큼 적힌 순서대로 주문. `Fill` 목록을 돌려줌(차이가 없는 다리는 안 냄) |
| `ctx.log(name, value, **fields)` | 차트·사건 기록에 남길 값. `value` 는 수(참/거짓 아님), 아니면 `TypeError`. `value`·`fields` 에 NaN·무한대가 있으면 `ValueError`(기록·화면 JSON 을 깨지 않게 — 계산이 0 으로 나뉠 수 있으면 먼저 거르세요). 줄에 `ctx.now()` 시각 `t` 가 붙어 차트가 그 시각에 찍음(재생은 봉 시각) — **`t` 는 칸 이름으로 쓰지 마세요**(`ValueError`) |
| `ctx.running()` | 「중지」도 멈춤도 없으면 True |
| `ctx.now()` · `ctx.sleep(s)` | 지금 시각 · 기다리기(중지면 바로 깸). 재생에서는 재생 시계 |
| `ctx.market_open(leg)` | 그 다리로 **지금 주문할 수 있는가** — 장이 열렸고, 국내 다리는 09:00 부터(4장) |
| `ctx.roll(name)` | 그 다리를 다음 월물로 바꾸고 새 다리 객체를 돌려줌. **그 다리 보유가 0 일 때만**(아니면 `OrderRejected`). 멈춘 뒤엔 `Halted`, 중지 뒤엔 `OrderRejected("중지됨")` |

`leg` 자리에는 다리 이름(글자) 또는 `ctx.leg(name)` 객체를 씁니다.
**`ctx.roll` 뒤에는 옛 다리 객체가 낡은 것**이라 주문·시세에 쓰면 `OrderRejected` 입니다. 이름으로 쓰거나 `ctx.leg(name)` 으로 다시 받으세요.

`Fill`(주문 결과, `ctx.order` 와 `ctx.target` 이 돌려줌):

| 칸 | 뜻 |
|---|---|
| `leg` | 다리 이름 |
| `qty` | 실제 체결 수량. **부호 = 방향**(매수 +, 매도 −) |
| `price` | 체결가 |
| `fee` | 수수료(모르면 `None`) |
| `price_known` | `False` 면 체결가를 읽지 못해 `price` 는 기준가(주문 때 가장 신선한 시세)입니다. **정확한 체결가로 믿고 손익을 계산하지 마세요.** 요약은 이런 체결이 든 손익을 「추정」으로 표시합니다 |

### 예외

- `OrderRejected` — 결과를 아는 실패: 거부·장 쉼·국내 09:00 전·최대 보유 초과·분당 주문 한도 초과·낡은 다리·중지 뒤 주문(`OrderRejected("중지됨")`). 잡고 다음 분에 다시 해도 됩니다.
- `TypeError` — 주문 수량이 정수가 아님(`1.5`·`True`·`"1"` 등). **아무것도 보내기 전에** 납니다(실행기 버그 — 「오류」로 끝나고 정리는 「중지」와 같음). numpy 수는 `int(...)` 로 바꿔 넘기세요.
- `Halted` — 실행이 **멈췄다**(주문 결과를 모름). 이 뒤 `ctx.order`·`ctx.target` 은 모두 `Halted` 이고, 화면 상태는 「확인 필요」입니다. 실행기는 `ctx.running()` 이 거짓이 되는 것을 보고 돌려주면 됩니다.
- 중지 뒤의 주문은 `Halted` 가 **아니라** `OrderRejected("중지됨")` 입니다(중지는 멈춤이 아님).
- 앱이 **끝내기를 시작한 뒤**(「중지」 뒤 30초가 지나 앱이 마무리를 시작했거나 앱 종료)에는 `ctx.quote`·`ctx.bars`·`ctx.next_minute` 도 `OrderRejected("중지됨 …")` 입니다 — 시세 조회도 나가지 않습니다(중지를 무시하고 도는 실행기가 NH 를 계속 부르지 않게). 중지 뒤 30초 안에는 시세를 아직 받을 수 있습니다.

## 3. `ctx.inherited` — 이어받은 실행의 상태 되살리기

이어받은 실행(7장)이면 다음 모양, 아니면 `None` 입니다(호출마다 복사본).

```
{"from": "앞선 실행 id", "ended_reason": "앞선 실행이 끝난 까닭",
 "legs": {"ho": {"qty": -1, "avg_price": 2.5012}, "rb": {"qty": 1, "avg_price": 2.4371}}}
```

`avg_price` 는 모르면 `None` 입니다. 시작 보유 자체는 `ctx.position` 으로도 보입니다. 롤링 창·진입 시각 같은 **실행기 자신의 상태는 앱이 되살려 주지 않습니다.**
이 값과 `ctx.bars` 로 직접 되살리세요(예제 참고). 손익은 새 실행 안에서 이어받은 평균가 기준으로 셉니다(평균가가 없으면 그 손익은 「추정」).

```python
LEGS = {"a": "HO", "b": "RB"}


def run(ctx):
    side = 0
    inh = ctx.inherited
    if inh:
        side = 1 if inh["legs"]["a"]["qty"] > 0 else -1 if inh["legs"]["a"]["qty"] < 0 else 0
    while ctx.running():
        m = ctx.next_minute(["a", "b"])
        if m is None:
            break
        ctx.log("gap", m.legs["a"].close - m.legs["b"].close, side=side)
```

## 4. 안전 규칙 (앱이 지킴)

- **주문은 `ctx` 로만.** 모든 주문은 모의(`paper`) 서버로만 나가고 재전송하지 않습니다.
- **`ctx.target` 은 보내기 전에 모두 검사합니다**: 달라지는 모든 다리의 장 열림·최대 보유·분당 주문 수. 하나라도 안 되면 **아무 주문도 내지 않고** `OrderRejected` 입니다(반쪽 짝 방지).
- 검사를 통과한 뒤 **뒤 다리가 거부**되면 같은 호출에서 이미 체결된 다리를 **시장가로 한 번 되돌립니다**(한도·분당 수에 걸리지 않음). 되돌리기도 거부되면 멈춤입니다.
  - 되돌리기는 그 다리 보유가 **체결 직후 값 그대로일 때만** 냅니다. 그 사이 앱 정리가 그 다리를 이미 움직였으면 내지 않고 멈춥니다(눈먼 반대 주문이 반대 보유를 만들지 않게).
  - 앱이 **끝내는 중**(중지 뒤 마무리·앱 종료)이면 되돌리지 않습니다 — 남은 반쪽은 앱 정리가 맡고, 앱 종료면 보유가 남아 「이어받기」로 보입니다(사건 기록에 「되돌리기 건너뜀」).
- **결과를 모르는 주문**(응답 없음·번호 없음·확인 시간 안에 체결 확인 안 됨)이 하나라도 있으면 실행이 멈춥니다(「확인 필요」) — 더 주문하지 않고, 이후 `Halted`.
- `ctx.order` 로 직접 짝을 맞출 때(한 다리만 체결되면 다른 다리를 어떻게 할지)는 실행기 몫입니다. 될 수 있으면 `ctx.target` 을 쓰세요.
- 한도: 다리별 **최대 보유**(절댓값; 기본 `MAX_QTY`, 없으면 5; 다리마다 시작 화면에서 바꿈) · **분당 주문 수**(기본 10). 넘으면 `OrderRejected`.
  이어받은 보유가 최대 보유보다 크면 **0 쪽으로 줄이는 주문만** 받습니다(늘리거나 0 을 넘어 반대쪽으로 한도 밖이면 거부).
- 장이 쉬는 다리로는 주문하지 않습니다(`OrderRejected("장 쉼: …")`, 줄 세워 두지 않음). 국내 다리는 **v1 에서 주간 장만** 다룹니다 — 야간 장은 쉼으로 셉니다.
- **국내 다리의 주문은 09:00 부터**입니다(모의계좌 주문 시작). 주간 장 판정은 08:45 부터 열려 `next_minute` 는 08:45 봉부터 주지만, 08:45~08:59 의 주문은 `OrderRejected("주문 시간 전: …")` 이고 `ctx.market_open` 도 거짓입니다. 앱의 정리(「정리 대기」)도 국내 다리는 09:00 이 되어야 함께 냅니다.
- **같은 종목에 모의 계좌 실행은 하나**(스프레드·파이썬 전략 탭 통틀어). 시작할 때 다리 종목의 계좌 잔고가 모두 0 이어야 합니다(이어받기만 예외).
- 기록은 쓰는 순간 계좌·키·토큰을 지웁니다.

시작 거부(화면에 까닭이 뜸): 방식이 맞지 않음 · 주말 · 모의투자 환경이 아님(모의 계좌) · 실행기 파일 오류 · 다리를 못 찾음 ·
최대 보유·분당 주문 수가 양의 정수가 아님 · 같은 종목의 모의 계좌 실행이 이미 있음 · 시작 잔고가 0 이 아님.

## 5. 수명 — 「중지」까지 날을 넘겨 돕니다

- 실행 하나 = 실행기 파일 하나 × 「중지」까지. 상태: `준비` → `진행 중` / `장 쉼` → (`확인 필요`) → `끝` / `오류`.
- **`run` 이 돌려주면 실행이 끝납니다.** 보유가 남아 있으면 앱이 「중지」와 같이 정리합니다. 보유를 날 넘겨 들고 가려면 돌려주지 말고 `while ctx.running():` 으로 계속 도세요.
- 장이 쉬면 `next_minute` 가 열릴 때까지 기다립니다(상태 「장 쉼」). 실행기는 따로 기다릴 필요가 없습니다.
- 실행기가 예외를 내면 「오류」로 끝나고 **정리는 「중지」와 같이** 합니다.
- **「중지」**: `ctx.running()` 이 거짓이 되고 `next_minute`·`sleep` 이 깹니다. 실행기에게 **30초**를 주고, 그 안에 안 돌려줘도 앱은 그때부터 `ctx` 주문을 받지 않습니다. 그 뒤 앱이 남은 보유를 정리합니다(멈춤 상태면 정리하지 않음).
  - 보유한 모든 다리로 주문할 수 있으면(장 열림, 국내는 09:00 부터) 다리마다 시장가로 바로 정리합니다.
  - 한 다리라도 주문할 수 없으면 짝을 그대로 들고 **「정리 대기」** 로 기다렸다가 모두 주문할 수 있게 되면 함께 정리합니다.
  - 정리 주문이 거부되면 열린 다리는 마저 정리하고, 거부된 다리는 10초 뒤 다시(처음 포함 3번까지) 냅니다. 그래도 안 되면 멈춤(「확인 필요」)입니다. 결과를 모르면 바로 멈춥니다.
  - 종이 방식은 종이 장부에서 정리합니다.
- **앱을 끌 때·다시 켤 때(배포 포함)**: 새 실행을 막고, 도는 실행에 중지를 알립니다. **모의 계좌 보유는 정리하지 않습니다**(날을 넘겨 드는 전략이 배포 때마다 청산되지 않게).
  실행은 끝나고, 끝난 까닭이 「앱 종료 · 보유 남음 — 이어받기로 다시」 입니다. 다시 켤 때 끝나지 않은 실행 폴더를 잔고만 확인하고(주문 없음) 닫으며, 보유가 있으면 「재시작 · 확인 필요」입니다.
  종이·재생 방식은 앱을 끄면 장부의 보유를 정리합니다.
- 「정리 대기」 중에 앱을 끄면 정리하지 않고 끝납니다.
- 보유 중에는 주기적으로 계좌 잔고와 장부를 대조하고, 다르면 멈춥니다.

## 6. 손익·요약

- 실행 폴더: `~/NHFutures/state/spreads/<시작일>_<NAME>_<orders|paper>[_n]/` — `run.json` `journal.jsonl` `api_log.jsonl` `summary.json`. 모의 키가 없는 `NH_REPLAY=1` 이면 `state-replay`.
- 요약은 **날마다**와 **실행 전체**를 함께 담고, 손익·수수료는 **통화별**입니다(환산 없음).
- 날은 **한국시간 07:00** 에 바뀝니다 — 해외 밤 장의 자정 뒤 체결은 그 장이 연 날로, 국내 주간 장은 그날로 셉니다.
- 평균가 방식: 줄이는 체결의 (체결가 − 평균가) × 수량 × 점가치. 체결가를 모른 체결(`price_known` False)이나 이어받은 평균가가 없는 손익은 `estimated`(추정), 수수료를 모르는 체결은 `fee_unknown` 개수로 표시됩니다.

## 7. 이어받기 (사람이 하는 재개)

끝난 모의 계좌 실행의 다리 종목에 보유가 남아 있으면 그 실행 화면의 「이어받기」로 새 실행을 세웁니다.

- **같은 실행기 파일·같은 다리 종목·모의 계좌**일 때만. 앞선 실행이 끝난 상태여야 하고, 한 번만 이어받을 수 있습니다(이어받으면 「넘겨줌」으로 표시).
- 다리 종목은 **앞선 실행이 끝날 때의 종목**을 그대로 씁니다 — 앞선 실행이 `ctx.roll` 로 월물을 바꿨거나, 그 사이 `LEGS` 의 최근월물이 바뀌었어도 확인 화면에 보인 종목으로 이어받습니다.
- 앞선 실행이 멈춤(「확인 필요」)으로 끝났으면 장부 보유가 0 이어도 이어받기가 보입니다 — 결과를 모르는 주문이 계좌엔 들어갔을 수 있어, 확인 화면이 **계좌의 실제 잔고**를 보입니다.
- 확인 화면에 **계좌의 지금 잔고**(다리별 수량·평균가)와 앞선 실행의 끝 까닭을 보입니다. 앞선 실행이 「확인 필요」였으면 그 까닭과 「주문내역을 먼저 확인하세요」 경고도 보입니다. 사람이 확인해야 시작됩니다.
- 새 실행은 **확인 순간 다시 읽은 계좌 잔고**를 시작 보유로 삼습니다. 화면에서 본 값과 달라졌으면 시작하지 않고 다시 확인하게 합니다.
- 결과를 모르는 주문이 있었던 실행이라도 사람이 주문내역·잔고를 확인했다면 이어받을 수 있습니다. 앱은 그 주문을 다시 내지 않습니다.

## 8. 재생 — 서버 없이 같은 실행기를 csv 로

```
uv run python -m backend.team_spread.replay <실행기.py> <다리>=<csv>:<tick>:<tick_value>:<통화> ...
uv run python -m backend.team_spread.replay <실행기.py> <다리>=<csv>[:<통화>] ... --legs-from-master
```

- csv 칸은 파이썬 전략 재생과 같은 차트 칸: `ref_dt` `exch_tm` `open_pric` `high_pric` `low_pric` `close_pric`(`cum_trd_qty` 는 있으면 씀). `exch_tm` 은 봉 **시작** 시각입니다.
- 첫째 꼴은 다리마다 틱·틱 가치·통화를 직접 줍니다(통화가 `KRW` 면 국내, 아니면 해외). 둘째 꼴은 해외 다리를 마스터에서 읽고 통화만 줍니다(국내 다리는 틱을 직접 줘야 하므로 첫째 꼴).
- 시계는 봉 시각입니다. **체결 = 주문한 분의 다음 분 시가 ± 1틱**(살 때 +, 팔 때 −). 다음 분이 이어지지 않으면(장 쉼·날 바뀜·마지막 분·그 다리의 다음 봉이 채운 봉) **지금 분 종가 ± 1틱**입니다. 수수료는 시장별 종이 값입니다.
- 어느 한 다리에 봉이 없는 분은 그 다리가 쉬는 분이라 그 다리 주문이 거부되고, 어느 다리에도 봉이 없는 구간은 「장 쉼」으로 밝히고 건너뜁니다.
- csv 가 끝나면 `next_minute` 가 `None` 을 주고 `ctx.running()` 이 거짓이 됩니다. 실행기가 돌려주면 남은 보유를 마지막 분 종가 ± 1틱으로 정리합니다. 같은 입력은 같은 거래·손익입니다.
- 결과는 `<상태 폴더>/spreads/<첫 봉 날짜>_<NAME>_replay[_n]/` 에 실제 실행과 같은 꼴로 남습니다. 서버 접속·주문은 없습니다.
- 실제 실행기와 같은 `SpreadRun` 을 쓰므로 수명·정리·요약이 같습니다. 단, 재생은 `ctx.roll`(월물 교체)을 하지 않습니다(마스터가 없어 거절).

## 9. 첫 모의 장중에 확인할 것

1. **종이 먼저.** 첫 장중은 종이 방식으로 돌려 흐름(상태·장 쉼·기록)을 본다. 그다음 모의 계좌로 **작은 주문**(최대 보유 1)으로 돌린다.
2. 해외 CME 상품(HO·RB)의 주문 상태 코드·잔고 칸 이름이 MKU 와 같은 해외 응답인지 — `api_log.jsonl` 로 확인(기록이 아직 없음).
3. 밤을 넘기는 해외 체결에서 수수료(예수금 fee 누적)의 영업일이 어떻게 바뀌는지 — 날이 바뀌며 누적이 줄면 그 체결의 수수료는 모르는 값(`fee_unknown`)이 됩니다.
4. 2계약 이상 주문의 체결 확인(부분 체결 표시)이 1계약과 같은지.
5. 국내 다리: 부분 체결 뒤 취소했을 때 주문 응답의 `exec_qty` 칸이 맞는지(시험 기록으로는 확인 못 함).
6. CME 에너지의 장 쉼 시간이 시간표 판정과 맞는지.
