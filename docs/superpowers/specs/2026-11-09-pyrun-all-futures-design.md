# 파이썬 전략 탭 — 모든 선물 (1분봉 실행기) 설계

- 상태: 초안 2판 (2026-11-09 — 빌더 확인 질문 8개를 반영, 「(내 판단)」 표시) · 브랜치 `feat/pyrun-all-futures` (`feat/spread-tab` 위 — 스프레드 탭 부품을 같이 씀)
- 관련: 파이썬 전략 탭(`backend/team_pyrun/`, `docs/team/strategy-file-convention.md`), 스프레드 탭(`backend/team_spread/`,
  `docs/superpowers/specs/2026-11-08-spread-tab-design.md`)

## 1. 왜

파이썬 전략 탭의 1분봉 실행기는 지금 **국내 미국달러선물(`A75…`)과 SGX 미니 원달러(`MKU…`)만** 받는다(`markets.market_of`).
팀은 같은 방식(전략 파일 하나 = `on_minute` 전략 하나)으로 **다른 선물도** 돌리고 싶다 — 해외 계좌의 난방유(HO)·원유(CL)·
금(GC)이나 국내 코스피200·국채선물 같은 것. 스프레드 탭은 이미 「마스터에서 아무 선물이나 찾기」와 「종목마다 장 열림 판정」을
갖췄으니, 그 부품을 파이썬 전략 탭에도 쓴다.

해외 선물은 한국시간 자정을 넘겨 열리는 것이 많다(CME 미국 정규장 22:30~05:00 등). **자정을 넘는 장도 실행 하나로 돈다**
(사용자 결정: 07:00 경계 거래일).

## 2. 목표 · 안 하는 것 · 실패로 보는 것

목표
1. 1분봉 실행기가 **국내·해외 선물 어느 것이든**(4.1 의 범위) 모의 계좌·종이로 돈다. 탭은 하나, 계좌는 종목을 따라 자동.
2. **자정을 넘는 장**을 실행 하나로 돈다 — 실행의 「하루」는 07:00 에 시작하는 거래일.
3. 종목마다 **장 열림·쉼**을 운영자 세션 판정으로 보고, 닫혔거나 쉬는 동안엔 주문하지 않는다(지금 MKU 20:35~20:50 규칙의 일반화).
4. 매일 자동 시작·리플레이·종목 고르기 화면·작성 규칙 문서가 같이 넓어진다.

안 하는 것
- 초 단위 실시간 실행기(`realtime.py`, leadlag)는 그대로 — KRX 신호 → MKU 주문만.
- 국내 야간장, 국내 주식선물(4.1), 휴일 단축 장 인식(운영자 판정도 휴일을 모름 — `holidayAware: False`).
- 실행 하나 = 종목 하나 · 1계약은 그대로(여러 종목은 스프레드 탭).

실패로 보는 것 (기술적으로 돌아가도)
- 지금 돌던 전략(week02 국내, week03 MKU ORB, 팀의 국내 전략들)의 **매매가 달라지는 것**. 리플레이 결과가 한 글자라도 바뀌면 실패.
- 틱·틱 가치를 짐작해서 주문하는 것. 모르면 시작을 거부한다.
- 시간표를 모르는데 주문이 나가는 것.

## 3. 사용자가 정한 것

- 파이썬 전략 탭의 1분봉 실행기를 **모든 종목**으로 넓힌다.
- **2번: 07:00 경계 거래일** — 자정을 넘는 장도 실행 하나.
- 국내·해외 계좌를 **나누지 않는다** — 탭 하나, 계좌는 종목을 따라 자동, 국내는 지금과 똑같이 돈다.
- 실시간(leadlag) 실행기는 그대로. 스프레드 탭 부품을 쓰므로 `feat/spread-tab` 위에서 작업.
- (지난 원칙 그대로) 주문 재전송 금지, 결과 모르면 멈춤, 재시작 시 계좌 실행 자동 재개 안 함, 민감 정보 기록 금지, 모의(`paper`)만.

## 4. 설계

### 4.1 종목 고르기 — 스프레드 탭의 `legs.resolve` 를 그대로

실행 폼의 종목 칸은 **품목 뿌리**(`HO`, `A01`) 또는 **종목 코드**(`HOZ26`, `A016C000`)를 받는다. 뿌리면 시작 때 최근월물로
한 번 고르고 실행 내내 그 종목(지금 규칙 — 월물이 넘어가도 실행 중엔 안 바꿈). 찾기는 `team_spread.legs.resolve` 로 하고
그 결과 `Leg`(종목·품목·시장·거래소·통화·틱·틱 가치·만기)가 실행의 종목 정보다.

- **빈칸은 지금처럼**: 전략 `TICK` 이 MKU 틱(0.0001)이면 MKU 최근월물, 아니면 미국달러선물 최근월물(`run_market` 그대로).
  다른 품목은 종목 칸을 채워야 한다.
- **최근월물 규칙은 스프레드 탭·지금과 같다**(해외는 마스터의 근월 표지 `lmon_my`, 국내는 만기일이 안 지난 가장 가까운 월물).
  만기 며칠 전에 넘기는 규칙은 두지 않는다 — 다른 월물을 원하면 종목 코드를 적는다. 해외 판정은 최종 거래일의 단축 장을 모르므로
  만기 주간은 직접 확인한다(작성 규칙 한계에 적음). (내 판단)
- A75·MKU 를 `resolve` 로 찾은 값은 지금 상수와 같다(마스터 2026-11-04: `A756B000` 0.1·1,000원 KRW, `MKUX26` 0.0001·2.5 USD
  `FSGX`) — 시험이 이 같음을 확인한다.
- **해외**: 종목 마스터 `cme_fut`·`etc_fut` 의 거래 가능한 선물 줄 전부(`type F`·`trdf 0`). 틱 `tsiz`·틱 가치 `tval`·거래소
  `ExchName`, 통화는 해외 품목 세부정보 `cur_cd`. 시세 사용 신청이 없는 거래소는 준비 봉 조회에서 `ETR010` 으로 거절되고
  시작이 거부된다(메시지 그대로).
- **국내**: 확인 표(`legs._DOMESTIC_DETAIL_NAMES`)를 넓힌다. 표의 줄마다 **마스터 계약 크기 × 세부정보 틱 = 세부정보 틱 가치**
  교차 검사(이미 있는 `_domestic` 검사)가 맞아야만 쓴다. 기록(`domestic_product-detail`, 마스터 2026-11-04)으로 맞춰 본 값:

  | 뿌리 | 세부정보 줄 이름 | 틱 × 계약 크기 = 틱 가치(원) |
  |---|---|---|
  | A01 | 코스피200선물 | 0.05 × 250,000 = 12,500 |
  | A05 | 미니 코스피200선물 | 0.02 × 50,000 = 1,000 |
  | A06 | 코스닥150선물 | 0.1 × 10,000 = 1,000 |
  | A08 | KRX300선물 | 0.2 × 50,000 = 10,000 |
  | A04 | 코스피200변동성지수선물(VKOSPI) | 0.05 × 250,000 = 12,500 |
  | A65 · A66 · A67 · A70 | 3년·5년·10년·30년 국채선물(KTB·5KTB·10KTB·30KTB) | 0.01 × 1,000,000 = 10,000 |
  | A75 | 미국달러선물(USD) | 0.1 × 10,000 = 1,000 |
  | A76 · A77 | 엔선물(JPY) · 유로선물(EUR) | 0.1 × 10,000 = 1,000 |
  | A78 | 위안선물(CNH) | 0.01 × 100,000 = 1,000 |
  | AAG | 코스닥 글로벌 지수 | 0.1 × 10,000 = 1,000 |
  | AAL | KRX반도체 섹터지수선물 | 0.2 × 10,000 = 2,000 |

  **빼는 것**: 주식선물(마스터 `kospi_key` `STKFBASE`, 291개 품목 — 세부정보 줄이 없고 틱이 주가에 따라 바뀜), 세부정보 줄이
  없는 섹터지수(AA0·AA1·AA2·AA3·AAC·AAD·AAE), 야간 줄(`cme_tp night` — `_day_first` 가 주간 줄을 고름). 거절 메시지에 까닭.
  이 표는 스프레드 탭 다리에도 그대로 적용된다(같은 함수) — 스프레드 작성 규칙 문서의 「국내는 미국달러선물만」도 고친다.
- **틱 확인(시장 가드를 바꿈)**: 지금의 「종목 시장 ≠ 전략 TICK 의 시장이면 거부」 대신, **전략 `TICK`·`TICK_VALUE` 가 고른
  종목의 틱·틱 가치와 다르면 조회·주문 전에 거부**한다(메시지에 두 값). MKU 와 HO 처럼 틱이 같고 틱 가치가 다른 품목도 걸린다.
  국내·MKU 의 시작 때 서버 틱 확인(`api.spec()` — 품목 세부정보)은 지금처럼 한다.

### 4.2 실행의 시장 값

지금 `Market` 두 개(`DOMESTIC`·`OVERSEAS`)는 「국내 계좌냐 해외 계좌냐」와 「A75·MKU 의 고정 값」이 섞여 있다. 나눈다.

- **계좌 쪽**(어댑터·예수금 칸·주문 상태 코드)은 지금처럼 국내/해외 둘. 해외 어댑터에는 종목의 `exch_cd`(=`Leg.exchange`)·
  `cur_cd`(=`Leg.currency`)를 넘긴다(스프레드 탭과 같은 호출, `adapter_for(..., exch_cd=, cur_cd=)`).
- **종목 쪽**은 실행마다 `Leg` 에서: 통화(해외는 EUR·HKD·JPY 도 됨), 틱, 틱 가치.
- **종이 수수료·슬리피지**: 스프레드 탭과 같은 규칙 — 국내 690원, 해외 2(그 종목 통화) 체결마다, 슬리피지 1틱. 어림값임을 문서에 적는다.
  엔·홍콩달러처럼 2 가 거의 0 인 통화를 위해 전략 파일에 **없어도 되는 `PAPER_FEE`**(그 종목 통화, 체결마다)를 두면 그 값을 쓴다.
  모의 계좌 실행은 지금처럼 예수금의 수수료를 읽는다(`PAPER_FEE` 는 종이·리플레이에만). (내 판단)
- **빠진 장 시간 칸 채우기**(`fill_params`): 지금처럼 **MKU 만**(week03 ORB 파일용). 다른 품목은 Params 에 여섯 칸
  (`session_start` `session_end` `entry_start` `entry_end` `flatten_at` `hold_min`)을 적어야 하고, 없으면 시작 거부.
- **리플레이의 하루 최소 봉 수**: 250 은 미국달러선물만(지금 값), 다른 품목은 1.

### 4.3 장 열림·쉼 — 운영자 세션 판정 하나로

장중 실행은 **주문해도 되는가**를 스프레드 탭의 규칙과 같은 함수로 본다(지금 `team_spread.feed.order_open` 의 규칙):
운영자 판정(`sessions_routes.judged`)의 상태가 국내 `day`, 해외 `open`·`open-2`·`next-day` 이고, 국내는 09:00(모의 주문 시작)
이후일 때만 연다. 그 밖(`break`·`closed`·`unknown`·단일가·판정 오류)은 전부 닫힘.

- 이 판정이 지금의 `in_break(market, clock)` 자리를 그대로 대신한다 — 휴장 중 진입 대기·청산 미룸·정리 요청 미룸·중지 미룸·
  보내기 직전 관문(`may_send`)·끝낼 때 「정리 안 함 — 확인 필요」 문구까지 지금 MKU 규칙이 모든 종목에 걸린다. 문구의 시각은
  판정의 `since`~`until` 로.
- 두 패키지가 한 규칙을 쓰도록 판정 함수는 한 곳에 두고(`team_pyrun` 쪽 — `team_spread` 가 이미 `team_pyrun` 을 가져다 씀)
  스프레드 탭도 그것을 부르게 옮긴다.
- **시간표를 모르면 주문하지 않는다.** 지금 MKU 는 시간표 없이 20:35~20:50 고정으로 쉬었다 — 이제 MKU 도 시간표를 따른다.
  운영자가 앱을 켤 때와 07:00 마다 받아 두는 표다(`session_service.refresh_all`).
  - **시작 때**(모의 계좌·종이 둘 다): 판정이 그 종목을 모르면(`source` 가 `unknown` — 표가 없거나 그 품목 줄이 없음) **시작 거부**
    (「장 시간표에 이 종목이 없습니다」). 조용히 주문 안 하는 실행이 서지 않게. (내 판단)
  - **실행 중에** 판정이 `unknown`·오류가 되면 그동안 주문하지 않고, 상태가 바뀔 때 기록에 한 줄(「장 시간표 모름 — 주문 멈춤」).
  - 기록(`overseas_market-operations`, 실전 2026-09-09)에는 MKU 줄이 있다. 모의 서버 표에도 있는지는 첫 날 확인(6장).
- **국내 08:45~09:00** 은 지금·스프레드 탭과 같이 정리 주문도 내지 않는다(모의 주문이 09:00 부터).
- **시작 때 확인(해외만)**: 그 거래일의 마지막 장 끝(`trading_day_end` — 운영자 함수는 해외만 있음)이 `flatten_at` 보다 이르면
  시작 거부(「장이 정리 시각 전에 닫힘」). 국내는 지금처럼 이 검사가 없고, 만기일 단축 장은 주문 관문(판정 `day` 가 닫힘)이 막는다.
  해외 판정이 휴일을 모르므로 휴일 단축 장은 못 거른다 — 문서 한계에 적는다.

### 4.4 자정을 넘는 실행 — 거래일 시계

**거래일**은 한국시간 07:00 에 시작한다(`team_spread.pnl.TRADING_DAY_STARTS` — 같은 상수를 쓴다).

**자정 넘는 실행**은 이렇게 가린다: Params 의 장 시각 칸(`session_start` `session_end` `entry_start` `entry_end` `flatten_at`)
중 하나라도 07:00 보다 이르거나, 실행 끝(4.5)이 24:00 을 넘으면. 그런 실행만 아래 **거래일 시계**를 쓴다.
**그렇지 않은 실행은 지금과 한 글자도 다르지 않다**(달력 날짜·실제 시각) — 국내 전략과 MKU ORB 는 여기에 해당.

거래일 시계 (자정 넘는 실행만)
- 전략이 받는 봉·가격의 시각: 00:00~06:59 는 24를 더한다 — 01:30 → `"253000"`, 06:15 → `"301500"`. 범위는 `"070000"`~`"305959"`.
- 봉의 날짜(`m.date`): 그 거래일(자정 뒤 봉도 앞 날짜). 그래서 전략의 「날이 바뀌면 하루 새로」 코드는 다음 거래일 첫 봉에서 돈다.
- Params 의 장 시각 칸 중 07:00 보다 이른 값은 다음 날 새벽으로 읽어 24를 더한 값으로 바꿔 넣는다(`"045500"` → `"285500"`).
  `fill_params` 처럼 같은 이름의 하위 클래스로 — 전략의 비교(`p.entry_start <= m.time < p.entry_end`)가 고치지 않아도 맞는다.
  바꾼 값과 원래 값을 기록 첫머리에 남긴다.
- 실행 안의 모든 시각 비교(진입 창·정리·`hold_min`·재시도·준비 봉 자르기)는 이 시계로 한다. `hold_min` 은 분 셈이라 자정을 넘어도 맞다.
- 실행 이름·폴더 날짜·「오늘 앞선 실행」(손절 수·진입한 개장 이어받기)·주말 거부는 **거래일**로 센다.
- 장 열림 판정(4.3)·주문·잔고·기록의 `at`(실제 시각)은 실제 시각 그대로.
- **Params 밖 시각 상수는 앱이 못 바꾼다**(예: week03 `common.py` 의 `SESSION_END = "240000"`). 작성 규칙에 적는다:
  자정 넘는 전략은 시각을 Params 에 두거나 상수를 24:00 이상으로 적고, `datetime.strptime(m.time, …)` 처럼 24시 넘는 값을
  못 읽는 함수에 시각을 넣지 않는다(문자열 비교·`int(t[:2])*60+int(t[2:4])` 는 됨).
- **07:00 을 넘겨 이어지는 장은 07:00 에서 끊긴다.** 대부분은 맞는다(CME 여름 07:00~06:00·겨울 08:00~07:00, MKU 08:25~06:15,
  홍콩 야간 ~03:00). 겨울 ICE 유럽(10:00~08:00)의 07:00~08:00 한 시간은 쓰지 않는다 — 문서 한계에 적는다.

### 4.5 실행 끝

- **국내**: 지금처럼 15:31(모든 국내 품목). `flatten_at` 이 그 뒤인 전략도 지금처럼 15:31 끝내기에서 보유를 정리한다(거부 안 함).
- **해외**: **`flatten_at` + 5분**(실시간 실행기의 규칙과 같음). MKU 기본 정리 23:50 → 23:55 로 지금과 같다. 거래일 시계로
  `"310000"`(다음 날 07:00)을 넘으면 시작 거부. 「끝 시각 뒤」 시작 거부도 이 시각으로.
- `flatten_at` 은 늘 있다(MKU 는 채우고, 다른 품목은 없으면 거부 — 4.2). 그래서 07:00 경계 전에 반드시 정리 시각이 오고, 그래도
  남은 보유는 끝내기(지금 규칙)가 정리한다. 07:00 에 따로 강제 청산하는 규칙은 두지 않는다.

### 4.6 매일 자동 시작

- 예약에 **종목 칸**(품목 뿌리 또는 종목 코드)을 더한다. 빈칸은 지금처럼(TICK 으로 A75·MKU 최근월물). 뿌리로 두면 날마다
  그날의 최근월물로 시작한다(월물 넘김이 자동). 예약 저장 파일은 지금 것에 칸만 더하고, 칸이 없는 옛 예약은 빈칸으로 읽는다.
- **시작 시각 = 전략 `session_start` 5분 전**(실행의 시계로). week02(09:00)·MKU(채운 값 08:25)는 08:55·08:20 으로 지금과 같다.
  `session_start` 가 다른 국내 전략은 시작 시각이 바뀐다(예: 09:30 → 09:25) — 매매엔 영향 없음.
- 요일·「그날 이미 세움」·「그날 건너뜀」은 **실행의 거래일**로 센다. 그래서 금요일 거래일의 새벽(토요일 00:55)에 시작하는
  예약도 선다. 07:00 뒤에 시작하는 예약은 거래일 = 달력 날짜라 지금과 같다.
- 그 밖(앞선 실행이 확인 필요·오류면 막음, 하루 3번 시도, 재개 안 함)은 그대로.

### 4.7 기록·다시 켤 때

- `run.json`·`summary.json` 에 `product`·`exchange`·`tick`·`tick_value`·`overnight`(자정 넘는 실행인가)·`trading_date` 를 더한다
  (`market`·`currency` 는 지금도 있음). 앱을 다시 켤 때 정리(`registry.recover`)와 잔고 확인은 종목 코드를 다시 해석하지 않고
  이 값으로 어댑터를 만든다. 옛 기록(칸 없음)은 지금처럼 `market_of(sym)` 로.
- 스프레드 탭과의 「한 종목엔 주문 실행 하나」 잠금(`CROSS_LOCK`)은 종목 코드로 그대로.

### 4.8 리플레이

`uv run python -m backend.team_pyrun.replay <전략파일> <YYYYMMDD> <csv> [--market domestic|overseas] [--currency USD]`
- 시장·통화를 안 주면 지금처럼 TICK 으로(MKU 틱이면 해외 USD, 아니면 국내 KRW). 종이 수수료는 4.2 규칙.
- 자정 넘는 전략이면 `<YYYYMMDD>` 는 **거래일**이고 그날 07:00 부터 다음 날 07:00 전까지의 봉을 거래일 시계로 넣는다.
- 쉼: 서버 없는 리플레이엔 시간표가 없다. MKU(해외 + MKU 틱)는 지금처럼 20:35~20:50 고정, 다른 품목은 봉이 있는 시각을 열림으로 본다.

### 4.9 화면

  품목 줄은 지금처럼 보이되 까닭을 달고 못 고르게. 국내 확인 표는 화면에 베끼지 않고 서버가 내려준다(작은 조회 하나 —
