# Windows 설치 도우미

`NH FUTURES API Setup.exe` 는 PowerShell 을 열어 명령을 입력하던 설치 진입점을 Windows 창으로 제공하는 프로그램입니다. 완성된 앱만 복사하는 설치기가 아니라, 내려받은 소스 안에서 개발 도구와 프로젝트 의존성을 준비하고, 선택에 따라 앱 실행 파일과 바탕화면 바로가기를 만듭니다. Windows 10/11 의 .NET Framework 4.x 와 Windows PowerShell 5.1 을 대상으로 하며, macOS/Linux 는 대상이 아닙니다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `NH FUTURES API Setup.exe` | 프로젝트 루트에 포함된 설치 도우미. 소스 ZIP 과 `git clone` 에 함께 들어 있어 이용자가 컴파일하지 않습니다 |
| `scripts/setup/SetupForm.cs` | 600×450 기준의 6단계 설치 창. 위치·옵션·도구 확인, 진행률, 상세 로그, 안전한 취소 요청, 재시도, 실행 후 설치 창 종료를 제공합니다. 같은 사용자 계정에서 두 개가 동시에 실행되지 않습니다 |
| `scripts/setup/SetupCore.cs` | 프로젝트 파일·쓰기 권한 검사, 경로 인용, 숨긴 PowerShell 프로세스 실행과 출력 수집, 완료·취소 판정, 실행 정책 오류 재시도, 앱의 독립 프로세스 실행 |
| `scripts/bootstrap.ps1` | 실제 설치 절차. 창에서 실행되면 묻지 않고(`-NonInteractive`) 단계 이벤트를 출력합니다. 직접 실행하면 기존처럼 대화형으로 진행합니다. `-DryRun` 은 외부 명령을 실행하기 전에 끝납니다 |
| `scripts/build-setup.ps1` | Windows 에 있는 프레임워크 C# 컴파일러로 설치 도우미를 빌드합니다. `-SkipZip` 은 컴파일만 하고, 그냥 실행하면 소스와 함께 ZIP 으로 묶어 `desktop/setup-dist/` 아래 새 폴더에 냅니다 |
| `scripts/test-setup.ps1`, `scripts/setup/SetupTests.cs` | 오프라인 검사. PowerShell 구문·BOM, 미리보기, 경로 인용, 실행 정책 재시도, 완료 마커, 출력 파이프, 진행률 모델을 확인합니다. NH선물 서버에는 요청하지 않습니다 |
| `scripts/setup/LaunchFixture.cs` | 테스트에서만 컴파일하는 작은 실행 파일. 조기 종료 감지와 설치 창 종료 후 자식 프로세스 생존을 검증하며 실제 앱으로 배포하지 않습니다 |

## 설치 창의 동작

제목은 **NH FUTURES API 설치**입니다. 기본 클라이언트 영역은 600×450이며 Windows 배율에 따라 확대됩니다. 흰색 본문, 연회색 버튼 영역, 검은 글자, 녹색 진행 막대를 사용합니다. 기존 픽셀 새싹과 큰 카드 영역은 제거했습니다.

| 순서 | 화면 | 다음 동작 |
| --- | --- | --- |
| 1 | 설치 안내 | 설치 범위·인터넷 연결·인증 정보 입력 위치 안내 |
| 2 | 설치 위치 | 압축을 푼 기존 프로젝트 폴더 선택, 필수 파일·쓰기 권한 확인 |
| 3 | 설치 옵션 | 실행 파일·바로가기·도구 설치 동의 확인 |
| 4 | 설치 준비 | 선택 사항 요약, 도구 버전 조회 후 설치 시작 또는 작업 미리보기 |
| 5 | 설치 중 | 현재 단계, 부드러운 퍼센트 표시, 선택적으로 펼치는 로그, 취소 |
| 6 | 설치 결과 | 실행하기/닫기 또는 실패·취소·미리보기 후 설치 준비로 복귀 |

설치 위치는 새로 복사할 빈 대상 폴더가 아니라 **전체 소스가 이미 있는 폴더**입니다. 위치 변경은 전체 ZIP을 원하는 곳에 풀어 해당 폴더를 선택하는 방식입니다. 쓰기 검사는 고유한 임시 파일 하나를 생성하고 닫을 때 삭제하며, 하위 경로의 모든 권한이나 디스크 여유 공간까지 보장하지 않습니다.

- 앱 실행 파일 만들기, 바탕화면 바로가기 만들기, 도구 설치·약관 동의는 기본 선택입니다. 창을 여는 것만으로는 아무것도 설치하거나 전송하지 않으며, **설치 시작**을 눌러야 진행합니다. 동의를 해제하면 설치를 시작할 수 없습니다. 앱 실행 파일 만들기를 해제하면 바로가기 선택도 비활성화됩니다.
- 설치 준비의 `-CheckOnly`는 PATH를 현재 프로세스에서 새로 읽고 `node/uv/just --version`을 실행합니다. 재사용·설치 필요·업데이트 필요를 표시하며 다운로드·빌드·바로가기 생성은 하지 않습니다. 실제 설치 시 버전을 다시 검사합니다. 확인 자체가 실패하면 설치 시작을 막으며, 이전 화면에서 돌아와 재확인할 수 있습니다.
- **작업 미리보기**(`-DryRun`)는 선택한 작업의 순서만 보여 줍니다. 도구 실행·다운로드·빌드·바로가기 생성을 하지 않으며, 완료 후 실행하기 대신 설치 준비로 돌아갑니다.
- 실행 중에는 옵션을 바꿀 수 없습니다. **취소 또는 X**를 누르고 확인하면 고유한 `.cancel` 파일을 기록합니다. 현재 외부 명령이 끝난 뒤 다음 도구·설치 단계 진입 전 중단하고 결과 화면을 보여 줍니다. 마지막 단계 도중에 취소를 누르면 그 단계가 끝난 뒤 되돌릴 다음 단계가 없으므로 설치를 완료로 보고합니다. 창을 즉시 닫거나 자식 프로세스를 강제 종료하지 않습니다. 이미 설치된 항목은 유지하며 무응답 외부 명령의 즉시 중단은 지원하지 않습니다.
- 성공 후 **실행하기**는 앱 EXE를 별도 프로세스로 시작합니다. 시작 오류 또는 700ms 안의 조기 종료는 설치 창과 오류를 유지합니다. 그 외에는 설치 창이 닫히며 앱/서버를 종료하지 않습니다. 이 확인은 계좌·네트워크·API 준비 완료 검사가 아닙니다. 이후 앱 자체에서 발생한 오류까지 감지하지는 않습니다.
- 실행 파일 만들기를 끈 경우에는 **닫기**와 `just dev` 안내를 표시합니다. 기존 EXE가 남아 있더라도 실행하지 않습니다.
- 진행률은 `완료한 단계 수 ÷ 선택한 단계 수` 입니다. 다운로드 바이트 비율이나 남은 시간이 아니므로, 오래 걸리는 단계에서는 숫자가 한동안 멈춰 있을 수 있습니다. 표시값은 실제 완료 비율을 넘지 않게 보간되며, 실패하면 마지막 비율에서 멈추고 로그가 펼쳐집니다.

| 선택 | 단계 수 | 표시 |
| --- | --- | --- |
| 앱 생성 + 바로가기 | 5 | 0 → 20 → 40 → 60 → 80 → 100% |
| 앱 생성, 바로가기 제외 | 4 | 0 → 25 → 50 → 75 → 100% |
| 개발 환경만 준비 | 3 | 0 → 33 → 66 → 100% |

## 실행 정책과 성공 판정

- 첫 실행에는 실행 정책 옵션을 지정하지 않습니다. 설치가 시작되기 전에 실행 정책 오류(`PSSecurityException`, `UnauthorizedAccess`)로 막힌 경우에만 종료 코드 73 을 돌려주고, 창이 `-ExecutionPolicy Bypass`(프로세스 범위)로 한 번 다시 시도합니다. 사용자나 컴퓨터 범위의 정책을 바꾸거나 저장하지 않습니다.
- 재시도 프로세스는 회사 정책(MachinePolicy/UserPolicy)이 정의되어 있으면 설치 파일을 부르지 않고 74 로 중단합니다. 설치가 시작된 뒤의 오류는 자동으로 다시 실행하지 않습니다.
- 성공은 **종료 코드 0 + 표준 출력의 `begin` 과 `done` 이벤트**가 모두 있을 때입니다. 표준 오류의 문구는 완료 신호로 쓰지 않습니다.
- 취소는 표준 출력의 `cancelled` 이벤트와 전용 종료 코드 75를 함께 확인합니다. 실행 정책 재시도 대상이 아니며 실패/취소 상태에서는 100%를 표시하지 않습니다. 완료와 취소가 동시에 경합하면 프로세스의 실제 결과를 우선합니다.
- 실패 뒤 다시 시도하면 설치된 도구를 다시 검사하고 의존성과 선택한 빌드를 다시 진행합니다. 설치된 도구 제거나 이전 상태 복원은 제공하지 않습니다.

## 빌드와 검사 명령

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-setup.ps1 -SkipZip
```

첫 번째는 오프라인 검사입니다. 두 번째는 설치 도우미 소스를 바꿨을 때 다시 컴파일하는 명령이고, 나온 실행 파일을 **프로젝트 루트에 덮어쓴 뒤 소스와 함께 커밋**합니다. 그래야 소스 ZIP 으로 받은 사람이 받는 실행 파일이 그 소스로 만든 것이 됩니다. 되돌릴 때도 소스와 실행 파일을 함께 되돌립니다.

소스를 변경했다면 먼저 빌드하고 루트 EXE를 갱신한 다음 검사를 실행하세요. 화면 전환·취소·실행 후 종료까지 검사하려면 `test-setup.ps1 -Screenshot .\desktop\setup-dist\ui-review.png`를 사용합니다. 단계별 PNG가 같은 폴더에 생성됩니다. GUI 검사는 실제 도구 설치·바로가기 생성·거래 앱 실행 대신 오프라인 대체 명령과 테스트 실행 파일을 사용합니다. 스크린샷 옵션이 없는 CI 검사도 기본 실행 파일 시작/조기 종료 검증을 수행합니다.

**빌드가 같은 바이트로 재현되지는 않습니다.** 쓰는 C# 컴파일러가 결정적 빌드(`/deterministic`)를 지원하지 않는 옛 것이라, 같은 소스를 두 번 빌드해도 **빌드 시각 4바이트와 어셈블리 MVID 16바이트**가 달라집니다. 그래서 루트 실행 파일이 소스와 맞는지 보는 검사(`.github/workflows/setup-check.yml`)는 해시를 맞대지 않고 **그 두 자리만 빼고 바이트를 견줍니다.**

## 제약

- 실행 파일은 코드 서명되지 않았습니다. 배포 시 SmartScreen 이나 보안 제품의 확인이 필요할 수 있으며, 보안 설정을 끄거나 바꾸는 기능은 없습니다.
- winget 이 없고 도구 설치가 필요하면 앱 설치 관리자를 설치하도록 안내합니다. 이를 자동으로 설치하지는 않습니다.
- 설치 프로그램은 관리자 권한으로 전체를 실행하지 않습니다. 패키지 설치에 필요한 Windows 승인 창은 따로 표시될 수 있습니다.
- APP Key 와 Secret Key 는 설치 도우미에서 받지 않으며, NH선물 서버에 요청하지 않습니다. 앱 실행 버튼을 누르면 앱의 기존 시작 동작이 수행됩니다.
- 로그는 `%LOCALAPPDATA%\NHFutures\Setup\logs` 에 남습니다. 외부 패키지의 출력에는 개인 경로나 프록시 정보가 들어갈 수 있으므로 공유 전에 확인하세요. 자동으로 올리지 않습니다.
- 앱 실행에 필요한 WebView2 는 설치 도우미가 설치하지 않습니다.
- 무응답 설치 프로세스의 강제 종료나 롤백은 제공하지 않습니다.
